# 平台设置（platform_settings）

本模块规划只保留两项：**平台／租户／Agent 配置层级与继承规则**、**工单模式及停用流程**。0009_ticket_settings 已准备最小持久层迁移，新增 platform_ticket_policy、tenant_ticket_settings；Agent 配置仍归原模块。继承解析、模式切换、实时停用服务及页面尚未实现。

各模块已有配置继续由原模块管理，本模块不重复建设模型管理、运行限额、权限策略、人工服务、知识参数、数据保留、计费、渠道或评估配置，也不另建通用配置发布中心。模块索引见[架构规划](../../../../../docs/architecture.md)。

## 1. 平台／租户／Agent 配置层级与继承规则

### 三个层级

| 层级 | 职责 | 工单示例 |
|---|---|---|
| 平台级 | 声明可用能力及下层不可突破的边界 | 是否提供工单能力、允许内置还是外部模式 |
| 租户级 | 在平台允许范围内选择企业使用方式 | 选择 disabled、internal 或 external |
| Agent 级 | 继承租户配置，并在职责范围内进一步收紧 | 售后 Agent 可提议工单，咨询 Agent 仅查询或不使用 |

Agent 不能为自己切换另一套工单系统，也不能通过配置获得原本没有的工具权限。工单模式由租户统一选择，Agent 只控制自身是否使用及允许的操作范围。

平台身份与租户身份必须分开。现有 admin 仅代表部署租户管理员，不自动拥有跨租户平台权限；独立平台管理身份就绪前，平台边界继续由受控部署配置提供。租户和 Agent 归属由服务端认证与资源查询确定。

### 继承规则

- **默认值继承**：仅对原模块明确允许覆盖的字段，按 Agent 显式值 → 租户值 → 平台默认值解析；没有配置时使用原模块定义的默认值。
- **恢复继承**：删除当前层的覆盖值；false、空集合和明确的 disabled 都是有效选择，不能当作缺失值。
- **拒绝优先**：平台不提供或租户停用时，Agent 不能重新开启；上层允许不代表下层自动获得授权。
- **限制只能收紧**：原模块若定义上限或允许集合，下层不能扩大；超限覆盖应明确报错。具体字段、单位及校验仍由原模块负责。
- **权限独立校验**：继承得到的有效配置不是执行许可；policy、工具网关及业务服务继续检查身份、工具权限和资源归属。
- **来源可解释**：读取有效值时能说明来自平台、租户还是 Agent，以及受哪一层限制。
- **停用即时检查**：不能用 Agent 的历史配置快照绕过当前工单停用状态；新操作执行前由工单业务服务检查。

这些是跨模块共同遵循的规则，不要求把各模块的配置复制到平台设置表。Agent 配置由 agent_config 管理，授权由 policy 管理，模型等业务配置仍归原模块；本模块不拥有第二份配置事实。

## 2. 工单模式及停用流程

### 工单模式

| 模式 | 含义 | 前提 |
|---|---|---|
| internal | 使用平台内置工单 | 当前工单业务归 customer_service |
| external | 使用企业已有工单系统 | 外部适配器、权限映射、幂等与状态核查已就绪 |
| disabled | 不再受理新的工单操作，保留历史查询 | 正常停用前完成存量处理或交接 |

目标配置仅保留模式与必要的外部连接引用，不新增默认队列、确认策略等其他设置：

```yaml
ticketing:
  mode: internal                 # disabled / internal / external
  integration_id: null           # external 时必须引用本租户已就绪的连接
```

现有内置工单与人工确认行为保持不变；首次接入配置时明确映射为 internal，不能因缺少新配置突然停用。工单创建仍服从原业务确认规则，本模块不能绕过或降低确认要求。

external 模式下以外部系统作为工单状态事实源，不同时在内置系统重复创建工单。连接与适配器由业务集成维护，本模块只引用。未实现外部适配时不能提供可用的 external 选项。

### 正常停用流程

1. **申请停用**：检查未结工单、待确认提议、尚未确定结果的外部操作及受影响 Agent。
2. **停止新建（draining）**：拒绝新的工单提议、创建及尚未执行提议的确认；保留历史查询和既有工单的处理入口。待确认提议须明确失效或拒绝，不能继续创建新工单。
3. **处理存量**：完成未结工单，或执行明确的交接/迁移；核查已发出的外部操作，不能假定取消成功，也不能为停用而伪造已解决状态。
4. **完成停用（disabled）**：确认没有未交接的工单和未决操作后切换模式；历史记录继续可查，不删除业务数据。

“停止新建”是停用过渡状态，不能提前标为已停用。过渡期间保留原 internal/external 模式和连接，以便处理存量；工单模式与工单本身的 open/in_progress 等状态分别维护。

### 模式切换与恢复

- internal 与 external 互切前先停止新建并处理存量；历史记录保留原提供方和关联 ID，不随模式切换改写来源。
- 取消停用或重新启用前，检查平台允许范围及原提供方是否可用；不自动执行旧提议，不重复提交结果未知的外部请求。
- 紧急禁用可立即阻断后续执行，历史只读，未结项保留给管理员恢复或交接；已经发出的外部请求仍需核查。紧急禁用不能冒充正常存量处理完成。
- 停用检查必须覆盖直接 API、Agent 工具、人工确认和后台任务；仅隐藏页面按钮不算停用。
- 工单停用不影响普通问答、其他业务查询和人工接管；这些流程不能强制依赖工单创建成功。

本模块定义模式选择与停用规则，customer_service 负责工单事实、确认和存量处理，tool_gateway 负责工具调用，policy 负责授权。当前只准备持久层迁移，不拆分 ticketing 模块，不改变现有业务行为。迁移及字段说明见 [数据库迁移说明](../../../../../docs/database-migrations.md)。
