# 会话管理（conversation）

维护客户会话、消息账本、服务归属及模型上下文视图，为自动服务与人工协作提供一致事实。

本文是模块开发规划。当前实现以第 1 节和代码为准，其余内容为目标设计；P0/P1 表示建设优先级，不表示已经完成。跨模块约定见[独立开发规范](../../../../../docs/module-development.md)，全局索引见[模块架构](../../../../../docs/architecture.md)。

## 1. 当前实现与差距

已实现创建、绑定 Agent、消息账本、增量消息读取、有限模型历史、人工回复和关闭/重开。状态变化自动递增 revision，关闭/重开要求匹配版本且没有活跃运行；人工回复要求当前负责人或管理员。接管期间通过交接状态机处理。列表目前保留既有有限分页，复杂筛选和统一游标分页尚未补全。

## 2. 功能模块与优先级

P0：独立开发及稳定集成所需基础能力。P1：规模化、治理或复杂场景扩展。按现有能力增量交付，不重复重建已实现功能。

| 功能模块 | 功能点 | 优先级 |
|---|---|---|
| 会话生命周期 | 创建、绑定 Agent、状态转换、关闭与重开规则 | P0 |
| 消息账本 | 角色、时间、顺序、运行关联及不可变消息标识 | P0 |
| 上下文视图 | 有限历史、消息选择、系统确认结果与来源关联 | P0 |
| 归属控制 | 自动/等待/人工模式、负责人、并发版本检查 | P0 |
| 查询能力 | 游标分页、时间范围、客户/渠道筛选、历史检索 | P0 |
| 消息扩展 | 附件、引用、编辑/撤回事件、送达/已读状态 | P1 |
| 历史压缩 | 摘要、压缩版本、保留原始消息及重建能力 | P1 |
| 客户关联 | 跨渠道身份关联、客户档案引用与合并审批 | P1 |
| 数据生命周期 | 导出、归档、保留期限、删除与合法留存策略 | P1 |

## 3. 数据与状态归属

现有 `runtime_conversations`、`conversation_messages`。会话表虽有 runtime 前缀，目标所有者为本模块。规划独立 context_snapshots、参与者和消息投递状态；迁移前兼容原 Runtime 仓储。

现有表由已提交的 Alembic 迁移管理；本规划不创建新表。未来扩展使用新增迁移，避免修改已应用历史迁移。跨模块数据先明确所有者，再增加服务端口。

## 4. 接口与事件契约

以下 HTTP 路径均以 `/api/v1` 为前缀。目标方法、字段和事件为待实现契约，不能作为现有 API 调用。

当前接口：`GET/POST /conversations`、`GET /conversations/{id}`、`POST /conversations/{id}/human-replies`；客户 messages 接口实际由 customer_service 路由。

目标契约：`append_message(context, conversation_id, MessageInput, idempotency_key)`、`read_messages(context, cursor)`、`build_context(context, budget)`、`transition_mode(context, expected_revision, mode)`。返回稳定 message_id/seq 和版本；模式变更需显式命令，不能开放任意字段更新。

## 5. 依赖与职责边界

拥有消息事实和会话模式；customer_service 决定消息路由，human_handoff 管理接管流程，Runtime 只消费上下文并提交结果。附件内容由平台存储管理，客户身份由 identity/渠道提供。

独立开发不要求立即拆成微服务。先定义 Protocol/DTO 与假实现，由组合入口注入；新增跨模块调用不直接导入对方仓储。当前共享事务例外见独立开发规范。

## 6. 关键设计约束

- 账本消息与发给模型的上下文是两个概念，裁剪上下文不删除历史。
- 所有消息读取、游标查询和归属修改均验证租户及会话访问范围。
- 关闭、人工接管和自动结果写入必须受同一会话并发约束。
- 摘要只能作为派生视图，不能覆盖原始证据或制造业务确认。

## 7. 管理台规划

会话列表、搜索筛选、消息时间线、引用、运行关联和归属状态；后续增加附件与历史导出。

界面权限与后端校验保持一致；配置区分草稿和生效版本。加载、空数据、冲突、拒绝和失败均有明确反馈，未实现操作不显示为可用。

## 8. 实施阶段

- P0：收敛共享表访问到会话服务，统一模式转换和消息幂等契约，补齐分页。
- P1：上下文摘要、多模态消息、跨渠道关联及数据保留。

每阶段先冻结最小接口与验收用例，再实现领域服务、持久层、API 和页面；集成时验证与上下游的兼容性。

## 9. 独立开发验收

- 高于 200 条历史仍可通过游标完整读取，顺序稳定且无跨会话泄漏。
- 并发回复与模式切换不会产生不符合当前归属的自动消息。
- 上下文预算为零或很小时不影响完整消息账本。
- 使用假身份及假存储端口测试查询与状态规则，数据库验证排序和唯一约束。

上述为目标验收条件，不是已有测试覆盖声明。已验证范围参见项目 `docs/platform-validation.md`。交付需更新本节对应测试位置及第 1 节实现状态。

## Agent 工作台增量（0011）

会话新增 `source` 字段：业务会话默认为 `business`，Agent 工作台试聊为 `playground`。历史会话保留并默认业务来源。试聊创建校验 Agent 属于当前租户、已发布且未归档；消息继续使用现有客服服务提交 Runtime。

新增按 Agent 和来源筛选的分页列表 `GET /agents/{aid}/conversations`，以及按 `before` 消息序号向前读取的 `GET /conversations/{cid}/history`。所有读取校验当前租户，不改变原有会话列表和详情响应。来源不是隔离执行沙箱，试聊会实际调用已绑定能力。
