# 运行观测与审计（observability）

把运行、模型、工具和业务操作关联起来，为诊断、运营及权限追溯提供可信证据。

本文是模块开发规划。当前实现以第 1 节和代码为准，其余内容为目标设计；P0/P1 表示建设优先级，不表示已经完成。跨模块约定见[独立开发规范](../../../../../docs/module-development.md)，全局索引见[模块架构](../../../../../docs/architecture.md)。

## 1. 当前实现与差距

已实现运行/事件查看、基础汇总及审计；新增运行到模型与工具调用的关联查询，以及近 24 小时按操作、状态、计量单位分别聚合的网关统计。调用诊断保存元数据，不保存工具参数和响应正文；未知网关用量不按零计量。前端提供关联详情和网关统计。完整游标分页、指标导出、告警及成本账单核对尚未实现。

## 2. 功能模块与优先级

P0：独立开发及稳定集成所需基础能力。P1：规模化、治理或复杂场景扩展。按现有能力增量交付，不重复重建已实现功能。

| 功能模块 | 功能点 | 优先级 |
|---|---|---|
| 关联标识 | trace_id、run_id、conversation_id、工具/模型 call_id | P0 |
| 运行诊断 | 状态、事件顺序、失败原因、取消与重试记录 | P0 |
| 性能指标 | 排队/执行耗时、首 Token 延迟、吞吐和成功率 | P0 |
| 操作审计 | 主体、动作、资源、配置版本、前后差异摘要 | P0 |
| 安全日志 | 密钥脱敏、内容采样、访问权限及导出范围 | P0 |
| 检索与留存 | 分页、时间范围、过滤、归档及清理策略 | P1 |
| 告警 | 失败率、延迟、队列积压、预算及外部服务故障 | P1 |
| 链路集成 | 结构化日志、OpenTelemetry/指标后端按需接入 | P1 |
| 运营分析 | Agent/渠道/租户对比、业务完成率与成本关联 | P1 |

## 3. 数据与状态归属

现有 `audit_records`，读取 Runtime 运行/事件进行聚合。规划指标聚合表、告警规则和投递状态。领域事实仍归各业务模块；观测副本不能反向修改 Run 或工单状态。

现有表由已提交的 Alembic 迁移管理；本规划不创建新表。未来扩展使用新增迁移，避免修改已应用历史迁移。跨模块数据先明确所有者，再增加服务端口。

## 4. 接口与事件契约

以下 HTTP 路径均以 `/api/v1` 为前缀。目标方法、字段和事件为待实现契约，不能作为现有 API 调用。

当前接口：`GET /observability/summary`、`GET /observability/runs`、`GET /audit`；Run 事件通过 Runtime SSE 查询。

目标契约：`record_audit(context, AuditEvent)`、`record_metric(MetricPoint)`、`query_trace(context, trace_id)`。事件含 schema_version、occurred_at、actor_ref、resource_ref、outcome、correlation；审计与普通诊断日志采用不同留存及可靠性策略。

## 5. 依赖与职责边界

接收所有模块的事件和指标，通过只读接口聚合。模型计价及配额账本由 model_gateway 管理，业务状态由所属模块管理；此处只展示和关联。通知通道复用平台能力，不借用客户渠道凭据。

独立开发不要求立即拆成微服务。先定义 Protocol/DTO 与假实现，由组合入口注入；新增跨模块调用不直接导入对方仓储。当前共享事务例外见独立开发规范。

## 6. 关键设计约束

- 指标标签避免原始用户输入、无限增长的资源 ID 和敏感内容。
- 统计明确定义时间窗口、分母及失败/取消分类，未知用量不视作零费用。
- 普通遥测故障不应阻塞客服主链路；关键操作审计是否失败关闭须按动作等级明确定义。
- 审计可追溯但不意味着天然防篡改，若有合规要求需独立存储与访问控制。

## 7. 管理台规划

运行看板、轨迹详情、审计筛选、模型/工具诊断；后续增加告警、趋势、导出及数据保留设置。

界面权限与后端校验保持一致；配置区分草稿和生效版本。加载、空数据、冲突、拒绝和失败均有明确反馈，未实现操作不显示为可用。

## 8. 实施阶段

- P0：统一关联 ID 和事件结构，完善查询分页及敏感数据规则。
- P1：指标后端、告警、归档和跨模块运营报表。

每阶段先冻结最小接口与验收用例，再实现领域服务、持久层、API 和页面；集成时验证与上下游的兼容性。

## 9. 独立开发验收

- 一次会话可关联模型调用、工具调用、人工接管和业务确认。
- 失败、取消与重试不会被错误计为成功，聚合可与原始事实核对。
- 无权角色不能读取审计或跨租户轨迹，密钥不进入日志。
- 用固定事件样本验证统计，用假遥测后端验证故障隔离。

上述为目标验收条件，不是已有测试覆盖声明。已验证范围参见项目 `docs/platform-validation.md`。交付需更新本节对应测试位置及第 1 节实现状态。
