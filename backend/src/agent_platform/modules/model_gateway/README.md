# 模型网关

模型网关统一管理模型接入、调用协议、路由、稳定性、权限和用量。Agent Runtime 表达所需能力，由网关选择模型和凭据，并处理模型调用失败。

能力范围明确包含 **Chat、Embedding、Rerank、语音模型（ASR/TTS）和 OCR**。统一的是配置、身份、预算和调用治理，各类模型保持独立输入输出协议，不全部套用聊天接口。语音指音频识别及合成。

本文包含当前实现说明及后续功能规划。下述规划能力不代表已经实现。

实现状态核对日期：2026-09-21。**第 1 节为当前交付清单；第 2～9 节涉及的目标设计、规划和验收条件不等于全部已实现。** “已实现”指已有代码和对应测试，不表示所有真实供应商都已完成部署验收。

## 1. 当前实现

治理扩展已实现：服务端分页、限定方案的访问密钥、文本敏感词输入输出拦截、租户/密钥数据库配额、单位定价与费用估算、历史区间统计、站内告警规则及事件确认。迁移版本为 `0010_gateway_governance`，部署、接口、测试和边界见 [治理与联调说明](../../../../../docs/model-gateway-governance.md)。后文规划表中的钱包计费、语义审核、Token 预算及灰度等仍不代表已实现。

已落地第一版配置—发布—调用闭环。实际请求格式、部署方法和供应商契约见 [PROTOCOL.md](PROTOCOL.md)；本文后续章节仍包含规划，不代表所有 P0/P1 均已完成。

- PostgreSQL `gateway_*` 表保存供应商连接、模型目录、配置方案及不可变发布版本、调用/尝试记录、临时媒体；基础迁移为 `0003_model_gateway`，治理扩展为 `0010_gateway_governance`（父版本 `0009_ticket_settings`）。迁移位于 `backend/migrations/versions/`。
- 六种 operation：Chat、Embedding、Rerank、ASR、TTS、OCR。使用独立请求 Schema、同一结果信封，支持 demo 与真实 HTTP 适配。
- `openai_compatible` 接入 Chat Completions、Embedding、文件 ASR/TTS；`gateway_http` 为自建服务提供六类明确的非流式契约，Rerank/OCR 需要提供方实现适配。
- Chat 支持 SSE 文本和工具参数增量、有限缓冲、断开取消；已输出内容后失败不重试、不切换模型。Runtime 仍按完整模型回复推进工具循环。
- 管理台新增“模型网关”：连接与模型配置、凭据引用状态、连接检测、方案发布/回滚、六类请求试用、媒体上传/音频播放、调用记录。
- Agent 可绑定 `model_profile_id + model_profile_version`，发布时校验 Chat/工具能力，Run 保存版本引用；未绑定时继续使用原 `.env` 部署默认模型。
- operation 并发隔离、共享连接额度、总超时、取消、有限重试和兼容主备模型；**operation/供应商连接并发按进程生效**。新增租户/访问密钥请求及并发配额通过 PostgreSQL 事务、锁和租约跨进程生效，两者不能混同。
- 供应商连接支持直接填写 API Key（独立表加密保存）或受控环境变量凭据引用；网关访问密钥仅保存摘要，创建/轮换时向授权管理员返回一次明文，不进入 Agent、Run 或调用日志。Admin 管配置，Operator 调用，Reader 看元数据。
- Embedding 校验输入映射、固定维度和向量空间；Rerank 校验候选 ID、数量及分数；OCR 校验页面对应关系。
- 默认只记录实际模型、状态、错误码、耗时及分项用量，未知用量为 null。提供方未返回的数据不会虚构成零费用。
- 媒体首版暂存 PostgreSQL，默认单文件 5 MB、租户总量 100 MB、有效期 24 小时；MinIO/S3、大媒体处理及自动定时清理仍待后续接入。

当前边界：OCR 只输出页面文本，ASR 只输出文件转写文本，尚不支持坐标/版面、说话人/时间戳、实时语音、自动能力探测、供应商密钥到期提醒、Token/金额预算、钱包结算、熔断或灰度。已实现的配额是租户/访问密钥请求及并发限制，费用是估算。本轮知识向量索引、Judge 与相似度评估已接入网关；Parser 仍使用独立的文档解析 HTTP 契约，尚未对接具体部署。demo 是明确标记的模拟结果，不代表真实模型质量。

代码：`contracts.py`（协议）、`catalog.py`（目录/版本）、`adapters.py`（供应商适配）、`gateway.py`（调用治理）、`routes.py`（调用/目录接口）、`governance_contracts.py`（治理协议）、`governance.py`（密钥/审核/配额/费用/告警）、`management_routes.py`（治理接口）、`reporting.py`（日志/统计）；`service.py` 保留原部署级 Chat 兼容入口。前端位于 `frontend/src/features/models/`，主要为 `ModelsPage.tsx`、`GatewayGovernance.tsx`、`GatewayReports.tsx`。

### 2.1 模型能力矩阵

同一供应商模型可声明多种能力，配置方案绑定具体 operation，不能根据模型名称推断接口兼容。LLM-as-a-Judge、摘要和文本抽取是 Chat 的应用配置，不是新增基础模型类型。

| 类别 | operation | 输入 | 输出 | 主要消费者 |
|---|---|---|---|---|
| Chat | chat | 消息、可选图像、工具 Schema、输出格式 | 文本/结构化内容、工具调用、结束原因及流式事件 | Runtime、摘要、Judge |
| Embedding | embed | 有序文本批次、query/document 用途 | 与输入对应的向量、维度及模型版本 | 知识索引/查询、评测相似度 |
| Rerank | rerank | 查询及带 ID 的候选文本 | 候选 ID、分数、排序 | 知识检索 |
| 语音 ASR | transcribe | 音频引用或受支持音频流、语言提示 | 转写文本；可选分段时间戳、说话人及增量结果 | 语音渠道或应用编排 |
| 语音 TTS | synthesize | 文本、语言、voice_id、输出格式 | 音频对象或受支持音频流、格式及用量 | 语音回复 |
| OCR | recognize | 页面/图片引用、可选区域、语言与输出要求 | 文本、区域位置；按能力提供表格/公式和识别质量信息 | Parser 适配器 |

首版语音包含文件级 ASR/TTS，流式识别、流式合成及双向实时语音在 P1 按供应商能力扩展，不默认所有模型支持。多模态 Chat 能理解图片，不等于能输出满足 OCR 定位要求的结果。

### 2.2 各类配置与能力约束

| 能力 | 必须管理的配置 | 按适配器声明的可选能力 |
|---|---|---|
| Chat | 消息/上下文限制、生成参数、工具及结构化输出支持 | 视觉输入、流式工具参数、特定输出格式 |
| Embedding | 模型版本、维度、输入上限、批量上限、query/document 编码方式 | 归一化、可变维度、Late Chunking 等专用能力 |
| Rerank | 候选数量/长度限制、top_n、截断策略、分数语义 | 返回文本、批量处理、特定领域模型 |
| ASR | 音频格式、采样率/声道要求、大小/时长上限、语言 | 自动语言识别、说话人分离、时间戳、流式转写 |
| TTS | voice_id、语言、格式、采样率、文本上限 | 语速、韵律、SSML、流式合成 |
| OCR | 图像格式、像素/页数限制、语言、区域及坐标约定 | 表格、公式、方向检测、版面结构、批量识别 |

不支持的参数在调用前拒绝或要求显式降级，不能忽略参数后仍声称完成。voice_id 是提供方允许的声音标识；声音克隆不在首版范围。格式转换和媒体预处理优先由媒体/Parser 适配层完成，网关负责输入能力校验及调用。

## 3. 配置层级

配置分为四层，凭据不存入 Agent 配置或 Run 快照：

```text
供应商连接
  └─ 地址、协议、凭据引用
       ↓
模型目录
  └─ 模型标识、能力、上下文限制
       ↓
模型配置方案
  └─ 模型、生成参数、超时、备用策略
       ↓
业务配置发布版本
  └─ Agent、知识库/索引、评测、语音或 Parser 配置引用相应方案
```

Agent 绑定模型配置方案，无需保存 API 地址和密钥。在线配置能力完成后，`.env` 主要保留启动配置、数据库连接及密钥服务配置；现有部署级模型参数可作为迁移期间的默认配置来源。

目标 ModelProfile 包含 operation、模型引用、能力要求、参数、预算和备用策略。当前 Profile 已包含 operation、模型引用、工具能力要求、聊天生成参数、总超时、重试和备用模型；Token/金额预算尚未实现。Agent 绑定 Chat；知识索引固定 Embedding，检索可绑定 Rerank；评测引用 Judge Chat 与可选 Embedding；语音应用分别引用 ASR/TTS；Parser 按需要引用 OCR（该集成尚待落地）。业务调用按 Run、job 或会话操作捕获版本，不要求所有操作创建 Runtime Run。

建议预设以下业务方案：

| 配置方案 | 使用场景 | 主要要求 |
|---|---|---|
| 客服快速问答 | 常见问题、普通知识问答 | 低延迟、支持工具调用 |
| 客服复杂处理 | 多步骤查询和复杂问题 | 较强推理能力、足够上下文 |
| 会话摘要 | 人工交接、历史压缩 | 结构化输出、较低成本 |
| 质量评分 | Judge 分维度评价回答 | 固定 rubric、结构化输出、校准版本 |
| 知识向量化 | 文档和查询编码 | 固定向量空间、维度、预处理及用途参数 |
| 检索重排 | 候选排序 | 保留候选 ID、受控输入预算 |
| 语音识别 | 客户录音转写 | 语言、格式、时长及转写质量 |
| 语音合成 | 将已确定回复转为音频 | voice_id、语言、音频格式及延迟 |
| 文档 OCR | 页面或区域识别 | 语言、坐标、输出类型与像素限制 |

## 4. 关键设计约束

### 运行配置固定版本

Run 创建时记录模型配置方案版本。每次模型调用记录实际供应商、模型以及路由结果，使后续配置变更不影响对历史运行的解释。密钥只保留引用，不进入快照和调用日志。

### 能力校验前置

发布时校验模型能力与 Agent 需求。例如启用工具调用的 Agent 必须绑定支持工具调用的模型；备用模型也必须满足该需求。参数应按实际供应商和模型能力校验，不应把不支持的参数直接透传。

### 重试与切换边界

未向客户端输出内容前，可根据错误类型执行有限重试或切换备用模型。已经输出流式内容后，不应静默切换模型并拼接答案。重试次数、等待时间和故障切换都必须受单次调用及 Run 总预算约束，并记录每次尝试。

非 Runtime 调用服从文档任务、评测或语音操作的总预算。备用路由必须同 operation 且满足输出契约：

- Embedding 不能因维度相同就切换不同向量空间；索引和查询使用固定兼容模型，迁移要重建并切换索引版本。
- Rerank 不保证不同模型分数同尺度，不混合两次模型的部分候选评分；降级保留原排序时显式标记。
- ASR 流式修订使用 segment_id、revision、is_final 等语义，不能将中间假设当作最终文本反复触发业务。
- TTS 已播放部分音频后不能静默换声音续接；错误和重启音频流需显式通知消费者。
- OCR 更换模型导致坐标/元素协议变化时由适配器转换并重新验证，不能混合不同解析配置的页面结果冒充同一版本。

### 分项计量与背压

调用信封统一 call_id、attempt_id、operation、profile_version、实际模型、状态、耗时及 usage。usage 同时保留提供方原始单位和可用标准项，未知数值标记未知；不把音频秒数、页数强行折算成 Token。供应商按 Token 或其他方式计费时按其实际计价版本估算。

Chat、embedding 批次、重排候选、音频时长及 OCR 像素消耗不同，按 operation 隔离并发预算，同时遵守共享供应商配额，避免批量 OCR/向量化占满客服 Chat 额度。流式消费者变慢时需要背压及缓冲上限，取消后停止继续读取或发送媒体。

### 媒体数据与来源

音频、页面图及结果音频以受控对象引用或受限流传输，不在普通日志保存大段二进制。引用必须校验租户、来源及有效期，不开放任意 URL 抓取。OCR 保留 page_id、区域定位及坐标空间，ASR 保留时间单位和分段位置；提供方缺少置信度时标记未提供，不伪造统一分数。

### 取消贯穿调用链

用户取消运行或人工接管后，将取消信号传递到模型请求，尽快终止请求并释放连接及并发额度。实际供应商是否停止计费，需以其服务行为为准。

### 模型重试不重放业务动作

网关只处理模型请求，不负责重试已经执行过的业务工具。业务写入的确认、幂等及结果核查仍由工具和客服业务模块负责。

### 费用区分估算与实账

按用量和价格版本估算调用费用，保留计价依据；供应商最终结算可能与估算不同。用量未知时明确标识未知，不能按零用量处理。

### 日志按需记录内容

默认记录模型、耗时、用量和错误等元数据。完整提示词与回复按权限、脱敏及留存策略开启，避免在常规诊断日志中暴露客户内容或凭据。

## 5. 管理台规划

以下为目标页面划分。当前已交付模型广场、供应商连接、配置方案、试用台、调用日志、监控、访问密钥、敏感词、告警和配额页面；预算、供应商凭据托管及模型对比等高级功能仍未实现，详见第 1.1 节。

新增“模型网关”入口，包含以下页面：

1. **供应商连接**：连接维护、启停、连通性测试。
2. **模型目录**：按 Chat、Embedding、Rerank、语音、OCR 分类登记及能力筛选。
3. **配置方案与路由**：按 operation 展示参数、发布回滚、业务绑定及兼容备用策略。
4. **凭据管理**：密钥引用、轮换、状态及权限管理。
5. **配额与预算**：限额、预算、超额策略及预警。
6. **调用记录**：按 Run/job/语音操作追踪调用、错误、重试与模型切换。
7. **用量与费用**：按租户、业务、operation、模型及供应商汇总，分开显示各计量单位。
8. **调试与评测**：Chat 对话、向量维度/相似度、候选重排、音频转写/播放、OCR 区域结果及回归验证。

页面随对应阶段交付，不将未实现功能展示为可用能力。

## 6. 实施阶段

### 第一阶段：完成配置到调用的闭环

```text
添加供应商
    → 配置凭据
    → 登记模型能力
    → 创建并发布配置方案
    → 业务绑定相应 operation 的配置方案
    → Runtime / 知识 / 评测 / 语音 / Parser 调用
    → 查看耗时、用量和错误
```

重点完成 P0 能力：统一调用接口、可管理配置、版本绑定、能力校验、基本超时与并发控制、取消、调用记录，以及兼容性测试。配置变更应可审计，历史运行应可追溯到实际模型与配置版本。

分步交付共用治理底座和 Chat，再接 Embedding/Rerank、文件级 ASR/TTS、OCR；五类均属于网关目标范围，不能只交付 Chat 就标记全部完成。每类先提供假适配器和契约样例，再选择实际供应商完成调用验收；没有配置真实服务的类别显示未配置。

### 第二阶段：完善运行治理

补齐配额和预算、费用估算、熔断与故障切换、灰度分流、模型对比评测，以及数据留存等扩展策略。针对实际供应商限额和客服负载进行验证与压测。

按需求扩展流式 ASR/TTS、双向语音、专用 OCR 输出和高级 embedding 能力。语音渠道接入、VAD、回声处理及打断编排不因网关支持模型接口而自动实现，需要对应应用单独集成。

## 7. 部署与模块边界

先作为现有 Python 后端中的独立模块，提供稳定的内部异步调用接口。多个应用需要共用网关，或需要独立扩容时，再拆成独立服务。

- **Agent Runtime**：编排模型与工具循环，控制 Run 状态和整体预算。
- **模型网关**：模型连接、协议适配、选型路由、模型请求稳定性和用量记录。
- **工具网关及客服业务**：工具授权、执行、业务确认和写入幂等。
- **平台观测与评测**：关联调用记录、展示运行指标，并复用模型网关开展评测。
- **知识服务**：组织文档/查询向量化、检索候选和 Milvus 索引，消费 Embedding/Rerank；网关不存储业务向量库。
- **Parser 适配器**：文件格式转换、页面处理、解析步骤及 Chunk 标准化；需要直接 OCR 推理时调用网关 recognize，不把完整文档任务交给网关调度。
- **语音应用/渠道**：音频接入、对话状态、端点检测和播放编排；调用 ASR/TTS，网关不负责完整电话会话管理。

如接入的 Foil/第三方 Parser 已封装 OCR 模型调用，知识服务仍只调用统一 Parser 端口；在供应商实际开放模型级 API 时才适配网关 OCR。已封装的整体解析调用可关联外部服务用量，但不能伪造不可见的内部模型调用记录或重复计费。保持单文档队列和独立文档 Worker 的简化方案，不新增 Layout/General 调度池。

普通模型 API 调用无需代码沙箱；未来若开放模型生成代码的执行能力，应单独设计执行环境与沙箱边界。

## 8. 数据归属与接口契约

共同遵循[独立开发规范](../../../../../docs/module-development.md)，模块总览见[架构索引](../../../../../docs/architecture.md)。

当前已有模型网关专属 PostgreSQL `gateway_*` 表和在线管理 API，包含目录/连接/方案及版本、调用及尝试、临时媒体、访问密钥、敏感词、审核与价格设置、配额与租约、费用和告警事件。基础表由 `0003_model_gateway` 创建，治理扩展由 `0010_gateway_governance` 创建。配置来自 Settings、经 `ChatModel.ainvoke(messages) -> AIMessage` 调用的旧路径仅作为未绑定网关方案时的部署级兼容入口。

模型网关拥有调用事实与费用估算；观测模块只读汇总，Agent 保存方案及版本引用。当前备用路由保存在方案中，价格依据保存在每次尝试的费用快照中，未实现独立路由规则及价格版本管理实体。供应商凭据支持独立表加密存储或环境变量引用，不复制到快照；外部 secrets 服务托管仍为规划。

目标内部端口设计（下列命名未逐项落地，不能据此认定对应基础能力未实现；当前使用 `ModelGateway.invoke` 加类型化 operation，部分高级响应字段仍待实现）：

- `resolve_profile(context, profile_id, version) -> ModelProfileSnapshot`：解析固定版本及能力。
- `chat(context, ChatRequest) -> ChatResponse`：消息、工具、输出格式、方案版本及预算；返回内容、工具调用及结束原因。替代规划中含义模糊的通用 invoke。
- `stream_chat(context, ChatRequest) -> AsyncIterator[ChatEvent]`：文本/工具参数增量、用量和终态。
- `embed(context, EmbeddingRequest) -> EmbeddingResponse`：有序文本批次、用途和方案；返回按 input_id 对齐的向量、维度、模型版本及逐项状态，不静默跳过失败项。
- `rerank(context, RerankRequest) -> RerankResponse`：query、候选 ID/文本、top_n；返回有效候选 ID、排序和分数，不能生成原列表不存在的候选。
- `transcribe(context, ASRRequest) -> ASRResponse`：音频引用及格式/语言；返回文本和能力支持的分段时间戳、说话人。流式模式另提供类型化 ASREvent。
- `synthesize(context, TTSRequest) -> TTSResponse`：文本、voice_id、语言和格式；返回受控音频引用、媒体规格和用量。流式模式另提供 AudioChunk/终态事件。
- `recognize(context, OCRRequest) -> OCRResponse`：有序图片/页面/区域引用及识别选项；返回关联 source_id 的文本、区域及所支持结构，保留坐标空间和逐项错误。
- `probe_connection(context, connection_id) -> ProbeResult`：兼容性与连通性诊断，不回显密钥。

上述命名为目标内部协议。当前代码以 `ModelGateway.invoke` 加 operation 请求类型提供统一内部调用，HTTP 路由和已交付边界见 PROTOCOL.md。请求以 operation 区分参数 Schema，响应的通用元数据与各类 payload 分离。较长 OCR/ASR 操作如采用提供方异步 API，适配器记录 provider_request_id 并封装查询/取消，但业务任务事实仍由调用模块持有。

规划事件为 model.call_started、model.call_completed、model.call_failed、model.route_changed，以 call_id 关联请求，以 attempt_id 区分重试或切换，遵循统一事件信封。这些名称并非当前 API 的承诺。

## 9. 独立开发验收

- 假供应商适配器覆盖成功、超时、取消、限流、协议错误及流式中断，无需真实密钥。
- Agent 引用固定方案版本，编辑草稿不改变已有 Run；不匹配的模型能力在发布或解析时被拒绝。
- 重试及切换服从剩余预算，已发送流式内容后不静默拼接另一模型输出。
- 取消释放连接和并发额度；供应商结果未知时明确记录，不伪报已停止计费。
- 供应商凭据不通过 API/前端返回，不进入快照和日志；网关访问密钥创建/轮换时仅向授权管理员返回一次明文，此后不可查询，轮换不污染历史记录。
- 按尝试关联用量及价格版本，未知用量不记作零费用，观测汇总可与调用记录核对。
- 真实供应商使用独立测试配置验证协议差异；模拟测试通过不等于模型质量达标。
- 五类能力分别有 Schema、假实现、正常/失败/取消样例；非 Chat 参数不会被误发到聊天接口。
- Embedding 保持输入与输出一一对应，维度/模型空间不匹配时拒绝写入或查询，批次部分失败可明确恢复。
- Rerank 返回的 ID 来自输入且不重复；top_n、候选超限、模型更换和显式降级均有确定行为。
- ASR 覆盖不支持格式、超长音频、静音和时间戳校验；启用流式时验证修订及终态不会重复触发业务。
- TTS 输出可按声明格式解码，voice_id/语言不支持时明确报错；取消和中途失败不能混接不同音色的流。
- OCR 覆盖旋转、多语言及按能力支持的表格/公式，文本与源页面/区域对应，坐标转换可核对；解析调度仍在 Parser/知识模块。
- 大批量 embedding/OCR 不耗尽 Chat 并发预算；计量按 operation 区分，媒体内容和凭据不进入普通日志。

以上为完整目标验收条件，未全部覆盖；当前交付能力、限制和测试位置见第 1 节及 PROTOCOL.md。真实供应商需要使用实际部署配置单独验收。
