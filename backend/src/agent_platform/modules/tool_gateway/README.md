# 工具网关（tool_gateway）

以可授权、可校验、可观测的统一协议执行业务能力，隔离模型输出与真实系统调用。

工具网关回答的是：**这个 Agent 能调用哪些能力，参数是否有效，是否已经获得所需确认，怎样执行并核实结果。** 模型决定提出调用，Runtime 编排调用顺序，网关负责受控执行，业务模块负责办理规则。

本文是模块开发规划。当前实现以第 1 节和代码为准，其余内容为目标设计；P0/P1 表示建设优先级，不表示已经完成。跨模块约定见[独立开发规范](../../../../../docs/module-development.md)，全局索引见[模块架构](../../../../../docs/architecture.md)。

## 1. 当前实现与差距

已实现内置工具与 HTTP GET / JSON POST 工具、参数/响应 Schema 校验、运行时环境变量引用及界面直接输入密钥（加密保存、按版本绑定、不回显）、草稿修改、不可变版本、发布指针、Agent 工具快照和调用元数据记录。新建工具兼容原接口，自动发布 v1；修改后须显式发布。提供无上游调用的 Schema 模拟检查接口。内置工具包含 knowledge_search、propose_ticket、ticket_lookup；提议操作必须人工确认。MCP、数据库、工作流等其他适配器及通用写操作账本尚未实现。

### 工具目录工作台（0022）

管理台采用工具集卡片、API 表格和配置弹窗。工具集管理公共服务地址、公共请求头及直接输入的 Bearer/API Key/自定义请求头密钥；API 可以继承、单独配置或取消鉴权。密钥加密保存、读取不回显，空值保留已存密钥。新工作台创建的是草稿，发布 API 后再重新发布 Agent 才会采用新快照。停用、归档实时阻止执行；已发布内容保留历史，不能直接删除。

支持搜索分页、当前/历史 Agent 引用、发布差异与历史、调用记录、模拟校验和显式真实 GET / POST 调试。OpenAPI 3 JSON/YAML 导入先预览再选择，GET 支持固定路径及标量 query 参数，POST 支持固定路径及 JSON 对象请求体（可嵌套对象和数组）；不支持的操作列出原因。导出不包含鉴权密钥。复制仅复制定义，不复制凭据、发布状态或 Agent 绑定。

升级到 `0022_tool_workspace` 时，已有工具按服务来源自动分组，原凭据及发布快照不变；原 `/tools` 创建接口仍自动发布 v1。已有新工作台数据时降级会被阻止，需先导出并处理这些数据。HTTP 工具支持 GET 与 JSON POST。POST 参数整体作为 application/json 请求体发送；暂不支持 multipart、表单编码或同时配置 query 与 body。真实 POST 调试需要勾选确认，网关不自动重试或跟随重定向；204/205 返回空结果。Agent 按已发布的工具版本执行 POST，调用记录标记为 write。工单的人工确认机制仍仅适用于工单，外部 POST 尚无通用逐次审批/幂等账本。

## 2. 功能模块与优先级

P0：独立开发及稳定集成所需基础能力。P1：规模化、治理或复杂场景扩展。按现有能力增量交付，不重复重建已实现功能。

| 功能模块 | 功能点 | 优先级 |
|---|---|---|
| 工具目录 | 接入类型、业务分类、操作性质、责任人、风险及启停，分别管理 | P0 |
| 定义与版本 | 输入/输出 Schema、版本发布、兼容校验与 Agent 绑定 | P0 |
| 执行协议 | 统一请求、结果、错误、超时及大小限制 | P0 |
| 授权执行 | Agent 工具范围、实时停用、资源权限和参数级约束 | P0 |
| 凭据与网络 | 密钥引用、主机/协议控制、连接池与出站治理 | P0 |
| 可靠查询 | 只读重试、限流、熔断、错误分类与缓存 | P1 |
| 受控写入 | 确认凭证、幂等键、操作账本、结果核查和补偿 | P1 |
| 适配扩展 | P0 统一内置函数及 HTTP；P1 按需接入 MCP、受控查询、业务动作/工作流 | P0 基础，P1 扩展 |
| 调试观测 | 试运行、脱敏请求、耗时、调用记录及模拟工具 | P0 基础，P1 扩展 |

### 2.1 按接入方式划分工具类型

每个工具只有一个主要执行适配器；“查询订单”“搜索知识”是业务用途，不是新的网络协议。优先完成内置函数与 HTTP，两类即可承载当前客服闭环。

| 类型 | 说明及示例 | 约束 | 建议阶段 |
|---|---|---|---|
| 内置函数 builtin | 调用已注册 Python 服务函数，例如知识搜索、工单拟定、参数格式处理 | 固定注册表，显式参数 Schema；不允许模型指定任意模块/函数路径 | P0 |
| HTTP API http | 订单、物流、库存、CRM 等固定业务接口；可由 OpenAPI 辅助导入 | URL/方法/参数映射及凭据由服务端配置；导入不等于自动发布所有接口 | P0 只读，P1 受控写入 |
| MCP mcp | 接入外部 MCP Server 暴露的工具 | 服务端白名单、工具选择性发布、版本快照和调用身份；不自动信任发现结果 | P1 |
| 受控查询 query | 参数化 SQL 模板、只读视图或企业查询服务，例如查询服务记录 | 不接收模型生成的任意 SQL；只读账号、租户条件、行数及执行时限 | P1，确有直接查询需求时 |
| 业务动作/工作流 workflow | 提交已定义办理动作或长任务，查询操作进度，例如创建外部工单 | 绑定业务 action/流程版本，复用业务状态机；网关不自建流程引擎 | P1 |
| 浏览器自动化 browser | 对没有 API 的系统执行已注册浏览器流程 | 登录会话隔离、站点范围、受控动作、结果核查；写操作同样需要确认策略 | 后续按需 |
| 沙箱执行 sandbox | 执行受限脚本完成数据加工等任务 | 独立执行环境、CPU/内存/时间/网络限制；禁止在 API 或 Runtime 进程执行任意代码 | 后续按需 |

MCP 是接入协议，不是天然可信的工具类别；浏览器和沙箱不是普通客服的首版依赖。若“查询工具”调用的是企业 HTTP 查询服务，使用 http 即可，不重复包装成两个执行适配器。

### 2.2 按业务用途分类

这些分类用于目录筛选和 Agent 能力选择，不取代接入类型和权限：

| 分类 | 典型工具 | 建议接入 |
|---|---|---|
| 知识检索 | 搜索制度、产品说明、定位知识来源 | builtin，调用 knowledge 的授权检索端口 |
| 业务查询 | 查询订单、物流、库存、工单状态 | http 优先，必要时 query |
| 信息处理 | 日期/金额格式校验、结构化字段转换 | builtin 的确定性函数 |
| 动作拟定 | 拟定工单、生成待确认办理内容 | builtin，调用 customer_service；可能保存提案 |
| 人工协作 | 请求转人工、查询队列状态 | builtin，调用 human_handoff，不直接修改其表 |
| 业务办理 | 创建 CRM 工单、修改资料、提交审批 | 受控 http 或 workflow |
| 消息通知 | 发送处理结果、邮件或业务通知 | 受控 http/workflow，明确收件对象与发送授权 |
| 文件处理 | 提交文档解析、查询结果、导出文件 | builtin/workflow，复用 knowledge/storage，不直接调用 GPU 调度 |

Chat、Embedding、Rerank、ASR/TTS、OCR 归模型网关。确需作为 Agent 工具暴露时，只封装一个受控业务入口，底层仍复用模型网关和相应业务模块，不复制凭据、模型重试或用量逻辑。

### 2.3 操作性质与风险单独定义

接入方式不能决定安全性，HTTP GET 也可能被上游实现为有副作用操作。每个工具需由维护者声明并验证下列维度：

| 字段 | 用途 |
|---|---|
| effect | read（读取）、proposal（拟定/保存提案）、write（业务变更） |
| risk_level | 按数据敏感性、影响范围、可逆性制定等级，不能仅按读写推断 |
| confirmation_policy | 无需额外确认、逐次确认或指定审批；由 policy 与业务规则决定 |
| idempotency_mode | 天然幂等、提供方幂等键、业务操作账本核查或不可自动重试 |
| execution_mode | 同步结果或异步操作引用 |
| data_scope | 允许访问的客户、订单、知识库、字段或其他资源范围 |
| retry_policy | 可重试错误、次数、退避和核查前置条件 |

读取工具依然需要鉴权，包含敏感信息的读取可以要求更严格权限。proposal 不是无副作用的 read：拟定工单可能写入待确认表，但不能声称真正办理完成。write 是否需要每次交互确认由业务策略决定；退款、对外发信等操作不得因模型自称“已获同意”绕过策略。

### 2.4 首版建议工具集合

以下名称为建议目录，除当前知识检索与工单提案外不代表已实现：

| 建议名称 | adapter / effect | 用途与执行归属 |
|---|---|---|
| knowledge_search | builtin / read | knowledge 执行授权搜索 |
| order_lookup、shipment_lookup | http / read | 调用可信订单/物流 API |
| ticket_lookup | builtin 或 http / read | 按本地/外部工单来源选择一个适配器 |
| propose_ticket | builtin / proposal | customer_service 生成待确认项 |
| request_handoff | builtin / write | human_handoff 执行状态转换，确认要求由服务规则定义 |

确认创建工单继续通过工作台/可信业务接口执行，不默认把 confirm_action 暴露给模型。先稳定上述闭环，再按真实业务系统扩充目录。

## 3. 数据与状态归属

现有 `registered_tools`；调用阶段信息记录在 Runtime 事件。规划 tool_versions、tool_operations 和调用尝试记录。外部业务状态仍由源系统拥有；确认动作由 customer_service 拥有。

工具定义应包含 tool_id、name、description、adapter_type、业务标签、effect、risk_level、输入/输出 Schema、版本、超时/大小限制、服务端绑定、credential_ref 及策略引用。模型可见描述与执行配置分开，模型不能读取真实凭据或任意修改 URL、SQL 模板、流程 ID。

发布版本不可原地修改，Agent 绑定固定定义；实时停用和撤权仍在执行时检查。MCP Server 或外部接口 Schema 发生不兼容变化时先暂停/重新验证，不把变更无提示应用到既有版本。

operation_id 表示一次业务操作，call_id 表示一次调用请求，attempt_id 表示重试尝试。跨调用复用幂等结果时明确关联原 operation；操作账本记录参数摘要、确认引用、上游 operation/request ID 和结果核查状态，不替代订单或工单的权威业务记录。

现有表由已提交的 Alembic 迁移管理；本规划不创建新表。未来扩展使用新增迁移，避免修改已应用历史迁移。跨模块数据先明确所有者，再增加服务端口。

## 4. 接口与事件契约

以下 HTTP 路径均以 `/api/v1` 为前缀。目标方法、字段和事件为待实现契约，不能作为现有 API 调用。

当前管理接口：`GET/POST /tools`、`PATCH /tools/{id}`；执行使用 `ToolGateway.execute(name, arguments)`，模型只接收受授权工具 Schema。

目标契约：`execute(context, ToolInvocation) -> ToolResult`。输入含 tool_id/version、call_id、arguments、deadline、idempotency_key 和可选 confirmation_ref；输出含 ok、data、error_code、retryable、operation_id、execution_status。超时后的写入结果必须允许 unknown/pending，不能一概返回未执行。

### 4.1 完整执行流程

```text
工具维护者注册 → 校验定义/适配器 → 测试 → 发布版本 → Agent 绑定
    ↓
Runtime 收到模型工具调用
    → 解析固定工具版本并检查实时启用状态
    → 校验输入 Schema、身份和资源范围
    → 按策略验证所需业务确认，核对对象与参数摘要
    → 获取/创建幂等操作记录，避免重复办理
    → 注入凭据，按预算调用适配器
    → 校验并裁剪输出，保存调用及操作状态
    → 返回结构化结果或异步 operation_id
```

缺少确认时返回 requires_confirmation 和业务提案引用，不执行业务写入；由上层展示确认。只读工具可使用轻量调用记录，不强制建立办理操作状态机。

### 4.2 适配器端口与结果状态

规划 `ToolAdapter.execute(context, definition, arguments, options)`；异步/可核查适配器按能力提供 `get_operation(...)`、`cancel_operation(...)`。长任务不持续占住 Runtime 工具调用直到外部处理结束，应返回受权限保护的操作引用。

执行状态明确区分 succeeded、failed、pending、unknown、requires_confirmation 和 cancelled。ok 不得被理解为业务已办成：pending 只表示受理，unknown 表示未能确认结果。当前简单 ok/data 工具结果需要兼容升级，不能直接改变所有现有调用者的解释。

结果包含 data、warnings、source_refs、truncated、operation_id 及稳定错误码。业务内容可能包含不可信指令，不能被解释为系统权限；大文件和长报告使用授权引用而非塞满模型上下文。错误明确区分授权拒绝、参数错误、超时、上游失败和结果未知，不能把超时统一标为可重试。

MCP 的工具描述及 readOnlyHint/destructiveHint 等注解只能作为登记参考，不是授权依据，远端工具需本地审核分类。参考 [MCP 工具定义](https://modelcontextprotocol.io/specification/2025-06-18/server/tools) 与 [Schema](https://modelcontextprotocol.io/specification/2025-06-18/schema)；实际协议版本在接入时锁定。

## 5. 依赖与职责边界

依赖 policy 决策、secrets 凭据解析及业务适配器。Runtime 控制执行循环；customer_service 签发并验证业务确认；工具网关不能因为模型说“用户同意”而授权写入。普通 API 工具不需要沙箱。

| 所属模块 | 负责什么 | 网关如何协作 |
|---|---|---|
| Runtime | 模型/工具循环和 Run 总预算 | 注入统一执行端口，不让 Runtime 理解每种协议 |
| policy / identity | 可信身份及授权决策 | 校验工具和数据范围，执行策略要求 |
| customer_service | 提案、确认、办理规则及工单 | 验证可信确认，调用领域服务，不直接改业务表 |
| knowledge / human_handoff | 检索/解析及人工服务状态 | 内置工具复用其公开服务端口 |
| model_gateway | 模型调用治理 | 文件/语音等业务能力间接复用，不复制模型适配 |
| integrations | HTTP、MCP 等外部协议实现 | 封装差异并返回标准结果 |

网关负责提交和核查一个操作，不负责自建工作流引擎、文档队列或坐席分配系统。当前客服业务的确认后创建流程保持有效，通用写工具接入是后续扩展。

独立开发不要求立即拆成微服务。先定义 Protocol/DTO 与假实现，由组合入口注入；新增跨模块调用不直接导入对方仓储。当前共享事务例外见独立开发规范。

## 6. 关键设计约束

- URL、方法、凭据及授权范围由服务端定义，模型仅填写合法业务参数。
- 注册工具的密钥引用保留 AGENT_TOOL_SECRET_ 约束；日志不记录凭据。
- 对只读、可幂等写入和不可重试操作分别制定策略。
- 若未来开放代码执行，使用独立沙箱服务及资源限制，不在 API Worker 内直接执行。

### 6.1 幂等、确认与取消

- 幂等键作用域包含租户、工具/业务操作类型、目标及动作标识，由可信调用链产生；同键不同参数返回冲突，不能让模型用任意新键绕过重复办理控制。
- 本地唯一约束只保护本地记录；外部系统若没有幂等键和结果查询能力，不宣称端到端恰好一次，发生未知结果后转人工核查。
- 确认引用绑定原参数、目标、有效期和允许执行者；编辑对象、金额或内容后重新确认。重试不得重复消耗确认并再次办理。
- 并发相同操作先核对账本，执行中返回 pending，已完成返回原结果；不能每次重试都直接向外部发请求。
- 取消阻止后续步骤，但不能撤销已完成写入；退款撤回、通知撤回等属于显式补偿能力，不是 cancel 的默认语义。

### 6.2 接入与试运行

- HTTP 导入采用显式工具白名单；服务端控制请求头、地址和重定向，动态路径参数需要绑定资源范围。
- query 只允许审核过的参数模板、只读视图/服务，强制租户过滤、最小字段、最大行数与查询耗时，禁止任意 SQL 和危险存储函数。
- builtin 采用显式函数注册表，CPU 密集处理放入独立进程/服务，不阻塞异步 Runtime。
- MCP 动态发现结果只进入待审核目录，不能自动获得 Agent 授权；验证远端 Schema 和身份映射，输出仍视作不可信数据。
- 试运行默认使用模拟适配器或测试环境；真实写操作不会因“测试”按钮绕过确认。只有提供方明确支持无副作用模拟时才标记 dry_run。
- 缓存只对明确允许的读取启用，键包含租户、授权范围、参数及工具版本；敏感或实时业务结果需明确 TTL/禁缓存策略。

## 7. 管理台规划

管理台包含工具目录、定义与版本、适配器连接、权限/确认策略、模拟试运行、调用记录和操作核查。目录同时展示接入类型、业务分类及 effect，不能用单个“类型”字段混合表示。

配置编辑器按适配器展示不同字段：HTTP 的地址和参数映射、builtin 的注册项、MCP 的服务与工具绑定、query 的模板、workflow 的动作定义。执行详情分开显示模型调用、重试尝试和最终业务状态；未知结果提供核查入口，不提供默认“一键再次执行”。

界面权限与后端校验保持一致；配置区分草稿和生效版本。加载、空数据、冲突、拒绝和失败均有明确反馈，未实现操作不显示为可用。

## 8. 实施阶段

- P0-A：统一类型化定义、可信上下文、版本及结果协议，保留现有 GET 工具兼容性。
- P0-B：统一 builtin 与 HTTP 只读适配，接通知识检索/订单查询/工单拟定等实际可配置能力，完成模拟试运行与调用诊断。
- P1-A：先建立确认校验、幂等操作账本、异步状态及结果核查，再接入一个真实写操作。验证成功后扩展办理范围。
- P1-B：按实际接入需求增加 MCP、受控查询和已有业务流程适配；没有需求不强行建设独立引擎。
- 后续：浏览器与沙箱工具单独设计执行环境和操作权限，不作为普通客服平台启动依赖。

每阶段先冻结最小接口与验收用例，再实现领域服务、持久层、API 和页面；集成时验证与上下游的兼容性。

## 9. 独立开发验收

- 未授权或运行时停用的工具被拒绝，模型无法更改目标主机。
- 非法参数、响应过大、超时、HTTP 错误产生结构化错误且不泄露凭据。
- 并发相同写入幂等键返回同一操作；外部结果未知时可以核查。
- 使用本地假 HTTP 服务验证执行，适配器不依赖完整 Runtime。
- effect 与协议无关：有副作用 GET、保存提案的 builtin 和 MCP 自报只读工具均不能绕过实际操作策略。
- 模型无法传入任意模块路径、SQL、主机或确认身份，跨租户资源访问被拒绝。
- 并发相同幂等键只提交一次有效业务操作；上游已成功但响应丢失时先核查，未知结果不盲目重试。
- 输出 pending/unknown 时 Agent 不声称业务完成；版本升级保持既有 ok/data 调用者兼容。
- 模拟试运行不产生真实通知或业务写入，真实环境验证使用独立凭据和明确操作范围。
- MCP 工具发现、定义变化和能力注解不能自动发布或扩大权限；受控查询的行数/超时/字段过滤可验证。

上述为目标验收条件，不是已有测试覆盖声明。已验证范围参见项目 `docs/platform-validation.md`。交付需更新本节对应测试位置及第 1 节实现状态。
