# Agent 配置与发布（agent_config）

管理 Agent 的行为定义、能力绑定与发布生命周期，为运行提供可追溯的配置快照。

本文是模块开发规划。当前实现以第 1 节和代码为准，其余内容为目标设计；P0/P1 表示建设优先级，不表示已经完成。跨模块约定见[独立开发规范](../../../../../docs/module-development.md)，全局索引见[模块架构](../../../../../docs/architecture.md)。

## 1. 当前实现与差距

已实现管理台卡片分页、独立配置工作台、Agent 对话记录与已发布版本试聊入口、草稿修订、发布版本、模型配置与工具版本固定、知识库绑定、名称搜索、归档/恢复和草稿差异查询。发布后运行使用不可变依赖快照，并检查资源实时启用状态。0004 之前的历史版本没有原始工具快照，兼容读取当前已发布工具；重新发布后才能完整固定。配置审批、灰度和批量导入尚未实现。

## 2. 功能模块与优先级

P0：独立开发及稳定集成所需基础能力。P1：规模化、治理或复杂场景扩展。按现有能力增量交付，不重复重建已实现功能。

| 功能模块 | 功能点 | 优先级 |
|---|---|---|
| Agent 目录 | 名称、说明、标签、归档与检索 | P0 |
| 行为配置 | 提示词、工具与知识库绑定、轮数预算及参数校验 | P0 |
| 模型绑定 | 引用模型网关已发布配置方案及版本 | P0 |
| 草稿协作 | 乐观锁、冲突提示、变更比较 | P0 |
| 发布管理 | 不可变版本、依赖校验、发布记录与回滚 | P0 |
| 评测门禁 | 关联评测报告、发布阈值、失败阻断与例外记录 | P1 |
| 环境管理 | 开发/测试/生产配置映射、导入导出与敏感字段剔除 | P1 |
| 灰度策略 | 指定流量或渠道试运行、观测结果后扩大范围 | P1 |
| 模板复用 | 业务模板、派生配置、批量升级预览 | P1 |

## 3. 数据与状态归属

现有 `agents`、`agent_versions`。规划模型方案引用、版本差异、发布审批/门禁结果与环境映射。已发布版本不原地修改；回滚仅调整当前发布指针。

现有表由已提交的 Alembic 迁移管理；本规划不创建新表。未来扩展使用新增迁移，避免修改已应用历史迁移。跨模块数据先明确所有者，再增加服务端口。

## 4. 接口与事件契约

以下 HTTP 路径均以 `/api/v1` 为前缀。目标方法、字段和事件为待实现契约，不能作为现有 API 调用。

当前接口：`GET/POST /agents`、`PUT /agents/{id}`、`GET /agents/{id}/versions`、`POST /agents/{id}/publish`、`POST /agents/{id}/rollback`。内部服务提供 `snapshot(tenant, agent_id, connection)`。

目标契约：`resolve_release(context, agent_id, version?) -> AgentRelease`，包含配置版本、模型方案引用、工具定义版本、知识访问范围、预算；不包含密钥。发布以 expected_revision 控制并发，冲突返回明确错误。规划事件 `agent.published`、`agent.rollback_completed`。

## 5. 依赖与职责边界

Agent 配置继续由本模块管理；[platform_settings](../platform_settings/README.md)（规划）只约定平台／租户／Agent 层级与继承规则，以及工单模式和停用流程，不另行管理默认模型或 Agent 发布。

依赖工具目录、知识库授权和未来模型方案查询接口；评测通过报告接口提供发布证据。只管理配置，不执行模型、业务工具或知识索引。模型方案由模型网关拥有，不能在此重复维护。

独立开发不要求立即拆成微服务。先定义 Protocol/DTO 与假实现，由组合入口注入；新增跨模块调用不直接导入对方仓储。当前共享事务例外见独立开发规范。

## 6. 关键设计约束

- 已有 Run 使用已捕获版本，新发布只影响后续 Run。
- 配置快照固定不等于永久授权：运行时停用工具、撤销权限仍须生效。
- 知识库引用默认使用当前有效文档；如果需要可重现评测，应显式绑定知识快照。
- 删除或停用被发布版本引用的资源，需要约定失效行为，不能静默替换。

## 7. 管理台规划

Agent 列表、配置编辑、依赖校验、版本差异、发布记录、回滚；后续增加评测门禁与灰度面板。

界面权限与后端校验保持一致；配置区分草稿和生效版本。加载、空数据、冲突、拒绝和失败均有明确反馈，未实现操作不显示为可用。

## 8. 实施阶段

- P0：统一发布快照契约，接入模型配置方案，补齐归档与配置差异。
- P1：评测门禁、环境映射、模板及灰度发布。

每阶段先冻结最小接口与验收用例，再实现领域服务、持久层、API 和页面；集成时验证与上下游的兼容性。

## 9. 独立开发验收

- 两个编辑者并发保存时只能按合法修订更新，旧修订明确冲突。
- 发布后修改草稿不改变已有 Run；回滚保留完整发布历史。
- 缺失模型能力、无权知识库或停用工具在发布/执行适当阶段被拒绝。
- 使用假的模型方案/工具目录即可独立测试发布流程。

上述为目标验收条件，不是已有测试覆盖声明。已验证范围参见项目 `docs/platform-validation.md`。交付需更新本节对应测试位置及第 1 节实现状态。

## 管理台接口增量（0011）

新增 `GET /agents/catalog`（名称、发布状态、归档筛选与真实分页）及 `GET /agents/{id}`。原 `GET /agents` 继续返回数组，兼容其他模块。对话来源、按 Agent 查询及历史消息分页由 conversation 模块提供。验证见 `backend/tests/test_agent_workspace.py`、`backend/tests/test_agent_workspace_migrations.py`、`frontend/tests/agents-workspace.spec.ts` 和 `frontend/tests/agents-fullstack.spec.ts`。


## 已归档智能体永久删除（0012）

`DELETE /agents/{aid}?revision=N` 仅管理员可用，删除前要求已归档且修订一致。渠道（包括已停用渠道）及评测引用会阻止删除；相关会话存在排队/运行任务、未完成人工协同或有效待确认操作时也拒绝。检查、解除历史会话关联、删除发布版本及配置、写入审计在同一事务执行；采用与消息入队一致的 admission lock 顺序。

历史会话保存原 ID/名称/发布版本并关闭，消息及运行快照保留；会话管理禁止重新打开带 deleted_agent 标记的会话。该元数据变更沿用项目当前共享事务集成方式。验证位于 test_agent_deletion.py 与 test_agent_deletion_migrations.py。


## 模型方案必选

Agent 不再回退到部署默认模型。允许未绑定模型的草稿保存；发布、回滚和运行必须绑定可用的已发布 Chat 模型方案及版本，否则返回 `agent_model_required`（HTTP 409）。旧版未绑定 Agent 需选择方案并重新发布，运行快照缺少模型绑定时同样阻断。

配置页面仅提供已发布且启用的 Chat 方案；空状态引导前往模型网关的配置方案页，支持刷新选项。跳转遵循未保存修改保护。

验证：`backend/tests/test_agent_model_required.py`、`backend/tests/test_model_gateway.py`、`frontend/tests/agent-model-required.spec.ts`。
