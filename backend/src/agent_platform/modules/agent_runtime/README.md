# Agent Runtime（agent_runtime）

以业务无关的异步执行图完成模型—工具循环，并管理 Run 的调度、预算、取消和生命周期。

本文是模块开发规划。当前实现以第 1 节和代码为准，其余内容为目标设计；P0/P1 表示建设优先级，不表示已经完成。跨模块约定见[独立开发规范](../../../../../docs/module-development.md)，全局索引见[模块架构](../../../../../docs/architecture.md)。

## 1. 当前实现与差距

已实现 LangGraph 异步执行、PostgreSQL 运行队列/租约、独立或内嵌 Worker、模型/工具预算、取消与事件回放。此次对齐 Agent 工具版本快照及统一工具结果，工具事件包含网关调用 ID、版本及执行状态，模型事件关联模型网关调用。普通客服直接执行 API 工具，无沙箱依赖。模型逐 Token 流式输出、跨进程统一并发配额和生产压力基线尚未验收。

## 2. 功能模块与优先级

P0：独立开发及稳定集成所需基础能力。P1：规模化、治理或复杂场景扩展。按现有能力增量交付，不重复重建已实现功能。

| 功能模块 | 功能点 | 优先级 |
|---|---|---|
| 执行协议 | 标准运行输入、模型/工具端口、配置快照、结果与错误 | P0 |
| 调度队列 | 持久队列、租约、会话互斥、容量控制和排队超时 | P0 |
| 资源预算 | 模型轮数、工具次数、时间预算、上下文及输出限制 | P0 |
| 取消与终态 | 取消传递、迟到结果拒绝、终态单次提交 | P0 |
| 事件流 | 有序阶段事件、游标重放、断连恢复、慢消费者处理 | P0 |
| 检查点恢复 | 节点状态保存、兼容版本、恢复前授权检查与副作用核查 | P1 |
| 暂停与继续 | 等待用户输入、业务确认及外部回执的持久挂起 | P1 |
| 公平调度 | 租户配额、优先级、背压及跨 Worker 全局并发控制 | P1 |
| 运行优化 | 受控工具并行、上下文压缩接口、逐 Token 事件 | P1 |

## 3. 数据与状态归属

现有 `runtime_runs`、`runtime_events`；`runtime_conversations` 的历史上下文目前也由仓储协作维护。Run 状态当前为 queued/running/completed/failed/cancelled。规划独立 checkpoints、运行步骤与等待条件；新增状态需同步迁移、API 和 UI。

现有表由已提交的 Alembic 迁移管理；本规划不创建新表。未来扩展使用新增迁移，避免修改已应用历史迁移。跨模块数据先明确所有者，再增加服务端口。

## 4. 接口与事件契约

以下 HTTP 路径均以 `/api/v1` 为前缀。目标方法、字段和事件为待实现契约，不能作为现有 API 调用。

当前接口：`POST /runs`、`GET /runs/{id}`、`POST /runs/{id}/cancel`、`GET /runs/{id}/events`。`RuntimeEngine.run(message, history, emit)` 由 Worker 调用。

目标契约：`submit(context, RunInput) -> RunRef`、`cancel(context, run_id)`、`stream_events(context, run_id, cursor)`；输入含 conversation_id、agent_release、message_ref 和 deadline，输出含 run_id、status、output_ref、usage、error。事件必须带序号及版本；不把图内部状态作为公开接口。

## 5. 依赖与职责边界

依赖模型与工具端口、可信执行上下文和持久层；由组合入口注入知识、工单等能力。引擎不引用客服领域实现，不决定是否退款、转人工或创建工单。会话消息账本目标由 conversation 独占管理。

独立开发不要求立即拆成微服务。先定义 Protocol/DTO 与假实现，由组合入口注入；新增跨模块调用不直接导入对方仓储。当前共享事务例外见独立开发规范。

## 6. 关键设计约束

- 沿用统一事务锁顺序；领取、续租、提交均验证租约持有者，终态不可被迟到 Worker 覆盖。
- 取消运行不代表撤销已经完成的外部副作用。
- 检查点恢复前必须核对工具操作账本；不能简单重跑写入节点。
- 时间预算覆盖排队后执行的模型、工具及重试；子调用不可无限延长 Run。

## 7. 管理台规划

运行列表、状态详情、事件轨迹、取消操作；未来增加等待原因、恢复操作及队列容量面板。

界面权限与后端校验保持一致；配置区分草稿和生效版本。加载、空数据、冲突、拒绝和失败均有明确反馈，未实现操作不显示为可用。

## 8. 实施阶段

- P0：稳定执行端口与事件契约，贯通模型网关取消及预算。
- P1：先建立工具操作账本，再实现检查点、持久暂停、公平调度和逐 Token 输出。

每阶段先冻结最小接口与验收用例，再实现领域服务、持久层、API 和页面；集成时验证与上下游的兼容性。

## 9. 独立开发验收

- 多 Worker 并发领取同一任务时只有一个有效执行者，同会话不存在两个活跃 Run。
- 人工接管或取消与结果提交竞争时，不产生迟到自动回复。
- 模型/工具超时、异常、断连均释放资源并产生可解释终态。
- 假模型和假工具可覆盖执行图；真实 PostgreSQL 验证租约、互斥和事件游标。

上述为目标验收条件，不是已有测试覆盖声明。已验证范围参见项目 `docs/platform-validation.md`。交付需更新本节对应测试位置及第 1 节实现状态。
