# 策略与权限（policy）

提供一致、可审计的授权与资源限制决策，防止模型或客户端扩大可访问范围。

本文是模块开发规划。当前实现以第 1 节和代码为准，其余内容为目标设计；P0/P1 表示建设优先级，不表示已经完成。跨模块约定见[独立开发规范](../../../../../docs/module-development.md)，全局索引见[模块架构](../../../../../docs/architecture.md)。

## 1. 当前实现与差距

已新增可信 `ExecutionContext`、统一 `Decision` 与默认拒绝策略，校验租户、角色、能力范围及资源启停；运行时每次工具调用仍检查实时撤权。API 保留既有角色依赖，资源归属由领域服务共同校验。个人员工凭证由身份基础设施提供。动态策略管理、组织授权和统一策略持久化尚未实现。

## 2. 功能模块与优先级

P0：独立开发及稳定集成所需基础能力。P1：规模化、治理或复杂场景扩展。按现有能力增量交付，不重复重建已实现功能。

| 功能模块 | 功能点 | 优先级 |
|---|---|---|
| 可信身份上下文 | 主体、租户、角色、来源及会话范围 | P0 |
| 基础授权 | admin/operator/viewer、资源归属、默认拒绝 | P0 |
| 能力授权 | Agent 工具、知识范围、模型方案及调用参数限制 | P0 |
| 统一决策 | allow/deny、原因码、约束和决策版本 | P0 |
| 策略管理 | 草稿、发布、回滚、规则优先级与冲突诊断 | P1 |
| 细粒度权限 | 组织/项目、资源 ACL、属性条件及委托范围 | P1 |
| 风险动作 | 动作风险分级、所需确认等级及审批条件 | P1 |
| 额度策略 | 声明租户/Agent 配额，委托对应网关原子计数 | P1 |
| 撤权与审计 | 实时失效、缓存版本、决策日志与模拟评估 | P0 撤权，P1 管理 |

## 3. 数据与状态归属

当前无独立策略表，角色来自配置、工具范围来自 Agent 发布配置。规划 policies、policy_versions、resource_grants、decision_records；主体账号由 identity 拥有。

现有表由已提交的 Alembic 迁移管理；本规划不创建新表。未来扩展使用新增迁移，避免修改已应用历史迁移。跨模块数据先明确所有者，再增加服务端口。

## 4. 接口与事件契约

以下 HTTP 路径均以 `/api/v1` 为前缀。目标方法、字段和事件为待实现契约，不能作为现有 API 调用。

当前 `/me` 提供身份，`/policy` 返回部署运行参数，不是策略编辑接口。内部 `check(tenant, name, allowed)` 和 `check_rounds(requested, settings)` 是现有入口。

目标契约：`authorize(context, action, resource, attributes) -> Decision`，含 effect、reason_code、policy_version、obligations（数据范围/确认要求/预算）。身份来自服务端认证；调用模块负责执行 obligations，不能只看 allow。

## 5. 依赖与职责边界

[platform_settings](../platform_settings/README.md)（规划）只约定配置层级与继承规则、工单模式及停用流程；policy 继续拥有授权决策，配置继承不能替代权限校验。

identity 负责认证主体，policy 负责授权决策；模型网关/Runtime/工具模块分别执行限流、预算与动作约束。业务确认由 customer_service 保存，policy 决定所需权限，不负责执行业务。

独立开发不要求立即拆成微服务。先定义 Protocol/DTO 与假实现，由组合入口注入；新增跨模块调用不直接导入对方仓储。当前共享事务例外见独立开发规范。

## 6. 关键设计约束

- 身份和租户不从模型参数读取；资源查询始终带可信范围。
- 发布快照可以记录策略版本，但撤权和紧急停用必须在执行时重新检查。
- 策略服务不可用时敏感操作默认拒绝；缓存允许范围与有效期需显式配置。
- 共享角色令牌不等于个人身份，审计不能把显示名称当认证主体。

## 7. 管理台规划

角色与访问范围、策略版本、决策模拟和拒绝原因；配额使用量由网关面板展示，避免重复计数。

界面权限与后端校验保持一致；配置区分草稿和生效版本。加载、空数据、冲突、拒绝和失败均有明确反馈，未实现操作不显示为可用。

## 8. 实施阶段

- P0：统一 ExecutionContext/Decision，收敛现有分散检查并保留行为兼容。
- P1：接入身份系统后扩展资源权限、策略发布、审批等级及缓存失效。

每阶段先冻结最小接口与验收用例，再实现领域服务、持久层、API 和页面；集成时验证与上下游的兼容性。

## 9. 独立开发验收

- 直接调用 API、后台 Worker 与工具执行均不能绕过权限。
- 跨租户资源 ID、伪造主体和无权知识库返回拒绝且不泄露数据。
- 撤权后新执行被阻断，缓存策略有明确失效测试。
- 使用固定身份与资源事实即可独立验证策略，无需模型联网。

上述为目标验收条件，不是已有测试覆盖声明。已验证范围参见项目 `docs/platform-validation.md`。交付需更新本节对应测试位置及第 1 节实现状态。
