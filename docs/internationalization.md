# 界面国际化

系统支持简体中文（`zh-CN`）、繁体中文（`zh-TW`）、英文（`en`）和印地语（`hi`）。主页面右上角及独立 Agent 配置工作台均提供语言选择。

首次访问按浏览器语言选择：`zh-TW`、`zh-HK`、`zh-MO`、`zh-Hant` 使用繁体，其他中文使用简体，英文使用英文，`hi` 和 `hi-IN` 使用印地语；不支持的语言回退简体。手动选择保存在当前浏览器的 `agent-platform-language` 中，优先于浏览器语言。它不是租户级或账号级设置。

切换语言即时更新界面、Ant Design 组件、日期和数字格式，不重置 hash 路由、表单草稿或筛选条件。费用始终使用原币种 CNY，只改变显示格式，不进行汇率换算。

## 文案维护

四个静态语言包位于 `frontend/src/i18n/locales`，通过 `frontend/src/i18n/index.ts` 使用 i18next。当前以简体源文案作为键；使用 `t('文案')`，插值使用 `{{name}}`，不要拼接英文句子或翻译后端标识符。模块级显示文案应在渲染时生成，避免语言切换后保留旧值。

新增界面文案需同步维护四个 JSON 文件，运行 `npm run check:i18n` 检查键和变量占位符，再运行 `npm run build`。`frontend/tests/i18n.spec.ts` 覆盖浏览器语言识别、偏好持久化、草稿保留、回复语言保存和行业筛选。

业务内容保持原文，包括 Agent 名称、提示词、案例介绍、知识文档和聊天记录。已有 9 个行业、18 个案例不会因切换界面语言而被改写；需要其他语言的案例内容时应另行维护。界面国际化也不代表中文知识库的跨语言检索质量已验证。

## 分类数据迁移

Alembic `0014_agent_locale_codes` 将已有行业和用途标签转换为稳定编码（如 `gaming`、`after_sales`），界面负责翻译显示。保留未知自定义行业、标签顺序和其他业务数据；降级可还原预置分类中文值。接口继续接受旧简体分类值并归一化，新的响应和 URL 使用编码。新环境执行 `alembic upgrade head` 后，案例初始化脚本直接写入编码。

## Agent 回复语言

Agent 运行参数新增 `reply_language`：`auto`、`zh-CN`、`zh-TW`、`en`、`hi`。未设置时默认 `auto`，跟随用户最新消息语言。此设置与界面语言独立，保存草稿并发布后才对新运行快照生效。运行时把语言规则添加到模型指令中，保留原有提示词及引用内容。实际回答取决于所绑定模型的语言能力；演示模型的固定输出不用于验证翻译质量。

新增印地语只扩展语言包、接口验证及运行时语言规则，`reply_language` 存于现有 JSON 配置中，无需新增数据库迁移。

模型绑定仍只接受已发布的 Chat 配置方案；本次没有恢复默认模型。
