# Phase 2 · 客户实体 + 画像/偏好记忆 — 业务目标

> 阶段：Phase 2（核心）
> 预估工期：~2-3 周
> 依赖：Phase 1 的 `memory_tasks` 任务表与 Memory Worker

## 要解决的问题

### 问题 1：老客户每次都像新客户

同一客户通过渠道（`session_id`）或开放平台（`external_user_id`）多次进线，Agent 对其历史一无所知：不知道他是谁、买过什么、偏好什么、之前解决过什么问题。客服行业最基本的"认出老客户"能力缺失。

### 问题 2：客户身份碎片化

系统目前有两套外部身份标识，互不相通：

- 渠道侧：`"channel:{channel_id}:{sha256(session_id)[:32]}"` 拼进会话 external_id（`modules/channel/service.py`）；
- 开放平台：`external_user_id` 存于 `open_sessions` / `open_runs`（迁移 `0025_open_platform.py`）。

没有客户实体，同一真实客户在不同入口是互不相干的"陌生人"。工单表预留的 `customer_id` 字段（VARCHAR(100)，迁移 `0008`）因此无人写入，始终为空。

### 问题 3：个性化只能全局配置

语言、回复风格等个性化需求目前只能在 Agent 配置层全局设置（`reply_language`），无法做到"这个客户偏好英文、那个客户偏好简洁回复"。

## 业务目标

| 目标 | 说明 |
|---|---|
| G1：统一客户身份 | 建立客户实体，渠道与开放平台身份都可解析到同一客户；为跨渠道合并留出扩展位 |
| G2：跨会话连续服务 | 客户再次进线时，Agent 自动知悉其画像（身份事实）与偏好，开口即个性化 |
| G3：激活工单 customer_id | 对话中识别出的客户身份写入工单，打通"对话—客户—工单"链路 |
| G4：记忆可人工管理 | 运营/坐席可在控制台查看、编辑、删除任一客户的记忆，纠正抽取错误 |

## 成功指标

| 指标 | 目标 |
|---|---|
| 回头客会话中 Agent 正确使用画像/偏好的比例（评估集） | ≥ 85% |
| 画像/偏好抽取的准确率（人工抽检 100 条） | ≥ 90% |
| 抽取的误报率（写入了对话中并不存在的事实） | ≤ 3% |
| 新建工单 customer_id 填充率（来源为已识别客户的会话） | ≥ 95% |
| 注入记忆带来的单轮 token 增量 | ≤ 1000 tokens |

## 范围

**包含**：
- 客户实体与身份绑定（`memory_customers` / `memory_identities`）；
- 画像记忆（profile：姓名、联系方式、账号、产品型号等身份事实）与偏好记忆（preference：语言、风格、称呼等）的自动抽取、存储、注入；
- 控制台记忆管理页（列表、查看、编辑、删除）；
- 工单创建时回写 `customer_id`；
- 抽取置信度机制（高置信自动生效，低置信进入待确认队列）。

**不包含**（后续阶段）：
- 事件记忆与工单生命周期联动（Phase 3）；
- 记忆的语义检索工具（Phase 3）；
- 标记记忆（VIP/风险）、TTL 过期、PII 脱敏、"忘记我"级联删除（Phase 4）；
- 跨渠道身份的人工/自动合并（Phase 4 治理项，Phase 2 仅表结构预留）。

## 风险与约束

- **抽取错误是最大的产品风险**：错误记忆（记错客户姓氏、张冠李戴）比没有记忆更伤体验。缓解：置信度阈值 + pending 队列人工确认 + 控制台随时可改可删 + 所有记忆可溯源到来源会话。
- **身份解析保守原则**：宁可不识别（当作新客户），不可错识别（把 A 的记忆给 B）。渠道侧 `session_id` 哈希唯一确定性高，可自动绑定；任何启发式匹配合并一律进人工队列。
- **数据污染防护**：playground 会话、示例 Agent（`is_example`）的对话不参与抽取。
