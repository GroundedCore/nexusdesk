确认本阶段交付物**功能正确**（AC 逐条复现通过）、**业务有效**（回头客识别与抽取质量指标达成）、**风险可控**（抽取错误可发现、可纠正、可溯源），并给出签字结论。

| 角色 | 职责 |
|---|---|
| 产品负责人 | 验收主持；记忆质量与个性化体验判定；P2 遗留处置签字 |
| QA | AC 场景执行与记录；回归结论；缺陷分级 |

| 合规/安全负责人 | 租户隔离与防污染判定 |

## 3. 功能验收清单（对应 AC-1~AC-8）

| # | 验收步骤 | 通过判据 |
|---|---|---|
| A1 | 渠道会话中客户说"我叫张三，电话 138****5678，以后用英文回复"，结束会话后同一渠道身份再次进线 | Agent 用英文问候并称呼"张三"；控制台客户详情可见对应 profile/preference 条目 |
| A2 | 同一 `session_id` 三次进线 | 三次会话绑定同一 customer；记忆逐次累积，不重复建档 |
| A3 | 构造抽取产出 confidence=0.6 条目（mock 可控输出） | 条目 pending；对话注入不含该条；控制台确认后注入出现；拒绝后永不出现 |
| A4 | 控制台编辑某条记忆内容 | 下一轮对话注入编辑后内容；条目展示人工来源；编辑前值可追溯（prev_content） |
| A5 | playground 会话提供个人信息 | 不产生客户档案与任何记忆条目 |
| A6 | 从已绑定客户的会话创建工单（propose→approve） | `tickets.customer_id` 已填充；工单详情可跳转客户记忆页 |
| A7 | 客户先说"我叫张三"，后说"其实叫我张工就行" | 称呼条目 update 为"张工"，revision=2，不堆叠两条 |
| A8 | Agent 分别关闭 `memory_write` / `memory_enabled` | 前者：对话不产生抽取；后者：不注入但抽取照常；互不影响 |

每个场景执行记录：执行人、日期、环境、前置数据、实际结果、判定、截图/日志链接。

## 4. UAT 操作清单（运营/坐席代表执行）

- 客户列表：搜索 external_key、分页、记忆条数与最近活跃时间展示；
- 客户详情：身份绑定列表、记忆按 type 分组展示（content/confidence/status/source_ref/updated_at）；
- `source_ref` 跳转来源会话；
- 编辑、软删除、恢复；
- pending 队列确认/拒绝；
- viewer 账号只读验证（所有写操作不可用）；
- 工单详情跳转客户记忆页。

## 5. 业务指标验收

| 指标 | 目标 | 测量方法 |
|---|---|---|
| 回头客会话画像/偏好正确使用率 | ≥ 85% | 评估集（≥ 20 个带预置画像的回头客 case）跑批，人工判分 |
| 抽取准确率 | ≥ 90% | 人工抽检 ≥ 100 条自动抽取条目（分层抽样 active/pending） |
| 抽取误报率 | ≤ 3% | 同上抽检中"对话中并不存在该事实"的占比 |
| 工单 customer_id 填充率 | ≥ 95% | 上线后统计：来源为已识别客户会话的新工单中填充比例 |
| 单轮注入 token 增量 | ≤ 1000 tokens | run trace 抽查 ≥ 20 个注入实例 |

## 7. 通过标准与签字

- **通过**：A1~A8 全部通过；抽取准确率 ≥ 90% 且误报率 ≤ 3%（硬指标）；合规项全过；UAT 清单无阻断问题；无 P0/P1 遗留。
- **有条件通过**：仅 P2/P3 遗留且每条有 owner 与期限，硬指标达标。
- **不通过**：任一否决项触发或硬指标未达标，修复后重验受影响项 + 回归。

输出《Phase 2 验收报告》：AC 执行记录表、抽检数据与达标判定、合规核对结果、遗留清单、结论与签字（产品 / QA / 研发 / 合规）。
