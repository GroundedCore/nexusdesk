# Phase 7 · 生产观测与告警 — 测试方案

> 状态：待实施（本阶段实现落地后执行）
> 创建：2026-10-17
> 依据：`02-requirements.md`（FR-1~FR-4、AC-1~AC-12）、`03-technical-design.md`（迁移 NNNN、采集补点、告警规则、D1~D3）

## 1. 测试范围与原则

**范围**：`memory_tasks` 时间戳列与耗时记录、检索模式事件扩展、维护/重试审计、十类观测指标聚合、八条告警规则、冷却与 webhook、前端分组卡片与告警列表。

**原则**：

1. **数值对账**：每个指标都用"构造已知数据 → 接口取值 → 与库直查比对"闭环验证，不接受"看起来合理"。
2. **时间类用例不等待**：最老任务年龄、维护超期、冷却窗口全部通过改库时间字段构造，告警检查手动触发单轮。
3. **告警宁漏不误**：小样本不判定（R4 调用数 < 20）、worker 重启重新采样（R3）、quickstart 形态豁免 R8——误报路径逐一验证为不触发。
4. **告警零敏感数据**：告警审计与 webhook 载荷正则扫描，无记忆明文/PII/连接串。
5. **既有观测不破坏**：`memory_summary` 既有字段语义不变（Phase 4 前端依赖），扩展纯新增。

## 2. 测试环境与数据构造

| 环境 | 用途 |
|---|---|
| 单测 | 告警规则求值纯函数（八条规则真值表）、冷却判定、降级口径选择（D3） |
| 集成（PG + pytest fixture） | 指标聚合对账、告警端到端、webhook mock、迁移回填 |
| quickstart 双容器 | TSVECTOR 形态检索模式分布、内嵌 Worker 告警周期执行 |
| pgvector 镜像 | vector 模式计数与降级率判定（复用 Phase 3 CI job） |

**数据构造约定**：失败任务直接 INSERT `status='failed'` 行；超龄 pending 用 `UPDATE run_after/created_at = now() - interval '61 minutes'`；维护超期用删除/改旧 `memory.maintenance.completed` 审计；webhook 用本地 mock HTTP server。

- Phase 1-4 记忆全量套件、Phase 5 配置套件、Phase 6 明细套件原样通过；

## 8. 缺陷分级与出口准则

| 级别 | 定义 | 处理 |
|---|---|---|
| P0 阻断 | 告警含敏感数据；告警检查阻塞任务主循环；观测接口拖垮库（全表扫描） | 修复并回归后方可继续 |
| P1 严重 | 指标数值与库不一致；告警该报不报（规则失效）；webhook 失败影响检查任务 | 修复前不得进入验收 |
| P2 一般 | 小样本/豁免边界误报；卡片展示错位；降级口径展示文案缺失 | 记录后可带问题验收，需产品签字 |
| P3 轻微 | 文案、样式问题 | 排期修复 |

**出口准则**：全部用例通过；AC-1~AC-12 复现通过；**告警零敏感数据、不阻塞主循环、指标对账一致为阻断项**；Phase 1-6 回归套件全绿；无 P0/P1 未关闭。
