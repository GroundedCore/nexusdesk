# Phase 7 · 生产观测与告警 — 验收方案

> 状态：待实施（本阶段上线前执行）
> 创建：2026-10-17
> 依据：`01-business-goals.md`（成功指标）、`02-requirements.md`（AC-1~AC-12）；测试执行依据见 `04-test-plan.md`

## 1. 验收目标与组织

确认本阶段交付物**健康度可视**（十类指标对账一致）、**告警主动发现**（八条规则该报必报、时延达标）、**轻量克制**（零新中间件、quickstart 形态可用、误报受控），并给出签字结论。

| 角色 | 职责 |
|---|---|
| 产品负责人 | 验收主持；观测页信息架构判定；P2 遗留处置签字 |
| QA | AC 场景执行与记录；指标对账复核；回归结论 |
| 研发负责人 | 环境保障；性能与对账数据出具；缺陷修复 |
| 平台运维 | **必到**：告警规则实用性判定；阈值默认值确认；故障演练执行 |

## 2. 验收环境与前置条件

| 环境 | 用途 |
|---|---|
| 类生产环境（真实模型 + pgvector PG + 累积数据） | 指标对账、告警触发、性能测量 |
| quickstart 双容器 | 内嵌 Worker 告警周期执行、TSVECTOR 形态检索指标 |

**前置条件**：`04-test-plan.md` 全部用例通过，无 P0/P1 未关闭；采集补点（事件/审计新字段）已上线观察 ≥ 1 天且数值对账无误（技术设计"上线与回滚"顺序）。

## 3. 功能验收清单（对应 AC-1~AC-12）

| # | 验收步骤 | 通过判据 |
|---|---|---|
| A1 | 打开观测页记忆卡片区 | 十类指标分组展示；抽 3 个指标与库直查对账一致 |
| A2 | 制造一个 memory_task 失败（构造错误 payload） | ≤ 30 分钟内出现 `memory.alert.task_failed` 记录；告警列表可见 |
| A3 | 保持失败条件持续 | 冷却窗内不重复告警；模拟冷却过期后再次告警 |
| A4 | 构造 pending 任务停留 61 分钟 | 触发积压告警，details 含最老年龄与阈值 |
| A5 | 阻塞规则扫描超 2 个周期 | 触发 `memory.alert.rule_scan_missed`；恢复正常后不再告警 |
| A6 | 改库使维护审计超 24h | 触发 `memory.alert.maintenance_silent`，overdue 列表正确 |
| A7 | quickstart 形态跑 ≥ 20 次检索；再跑 < 20 次 | 前者正确判定降级率；后者小样本不误报 |
| A8 | 配置 mock webhook 触发告警；再停掉 webhook 触发 | 前者收到合规 JSON；后者检查任务正常、审计仍落库 |
| A9 | 设 `memory_alert_enabled=false` 重复 A2 | 无告警记录；指标照常 |
| A10 | 两个 Agent 跑差异化流量 | Agent 维度注入率/写入量/失败量分别正确 |
| A11 | 无 `memory_injection_log` 的部署形态 | 注入指标按事件计数口径降级，无报错 |
| A12 | quickstart 双容器运行 1 小时 | 告警检查按周期执行（审计可见心跳/检查记录） |

每个场景执行记录：执行人、日期、环境、前置数据、实际结果、判定、截图/日志链接。

## 4. 故障演练（运维主导，验收重头戏）

| 演练 | 步骤 | 通过判据 |
|---|---|---|
| 演练 1：Worker 宕机 | 独立形态停掉 memory-worker 容器 | ≤ 30 分钟产生心跳缺失告警（R8）；pending 积压告警（R2）随后触发；恢复后无残留误报 |
| 演练 2：embedding 服务异常 | 阻断 embedding 调用（mock 网关 500）跑事件写入 | embedding_failed 积压上升；连续两周期触发 R3；恢复重试后积压清零 |
| 演练 3：pgvector 不可用 | 切 TSVECTOR 形态跑检索流量 | 检索模式卡片显示降级；超阈值触发 R4 |

## 5. 业务指标验收

| 指标 | 目标 | 测量方法 |
|---|---|---|
| 指标覆盖 | 十类全部可查且对账一致 | A1 + P7-IT-01~05 对账报告 |
| 告警发现时延 | ≤ 2 个检查周期（默认 ≤ 30 分钟） | §4 演练计时 |
| 告警误报率 | ≤ 20%（上线后首月） | 上线后观测期跟踪：误报标记数 / 总告警数 |
| 维护漏跑可发现 | 漏跑超 2 周期必告警 | A5/A6 |
| 零新中间件 | compose 无新增服务 | 部署清单核对 + quickstart 承诺复核 |

## 6. 合规核对

| # | 核对项 | 判定 |
|---|---|---|
| C1 | 告警审计与 webhook 载荷无记忆明文/PII/连接串/密钥（正则扫描） | 一票否决 |
| C2 | 告警检查不阻塞 memory_tasks claim 主循环（单轮 ≤ 5s） | 一票否决 |
| C3 | 指标聚合限时间窗，无全表扫描（explain 复核） | 必须通过 |
| C4 | `memory_alert_enabled=false` 可整体关闭 | 必须通过 |
| C5 | 观测指标与告警均按租户隔离 | 必须通过 |

## 7. 通过标准与签字

- **通过**：A1~A12 全部通过；三项故障演练达标；**C1/C2 为一票否决项**；无 P0/P1 遗留。
- **有条件通过**：仅 P2/P3 遗留且每条有 owner 与期限；误报率指标允许上线后观测期内跟踪。
- **不通过**：任一否决项触发或演练不达标，修复后重验受影响项 + 回归。

输出《Phase 7 验收报告》：AC 执行记录表、故障演练计时记录、指标对账数据、合规核对结果、阈值默认值确认记录、遗留清单、结论与签字（产品 / QA / 研发 / 运维）。
