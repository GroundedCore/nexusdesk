# Phase 7 · 生产观测与告警 — 业务目标

> 阶段：Phase 7
> 预估工期：~1-1.5 周
> 依赖：Phase 1-4（已上线）；注入明细类指标依赖 Phase 6 的 `memory_injection_log`（无则降级为计数口径）

## 要解决的问题

### 问题 1：记忆系统生产健康度无统一视图

Phase 4 已把记忆运营指标（抽取量、命中率、pending 积压、治理计数）接入观测页，但生产运维视角的健康指标缺失：记忆任务队列是否积压、embedding 是否失败、检索是否降级、维护任务（TTL/衰退/规则扫描）是否按时执行——这些出了问题只能等用户报障。

### 问题 2：故障发现靠人肉

记忆 Worker 挂掉、embedding 服务异常、pgvector 降级为文本检索、规则扫描漏跑——当前没有任何主动通知机制，故障发现时延取决于有没有人碰巧看观测页。

### 问题 3：按 Agent 维度的质量对比缺失

哪些 Agent 记忆注入率高、哪些写入量大、哪些失败多，无法按 `agent_id` 维度对比，无法支撑"记忆配置调优"（Phase 5 交付的配置开关需要数据反馈闭环）。

## 业务目标

| 目标 | 说明 |
|---|---|
| G1：健康度可视 | 任务队列、embedding、检索模式、维护任务、Agent 维度的健康指标全部进入观测页 |
| G2：故障主动发现 | 关键异常（任务失败、积压、降级率超标、维护漏跑）在分钟级产生告警记录 |
| G3：轻量先行 | 告警先落审计记录（可查询、可导出），外发通道（Webhook/企业微信/Slack）作为可选增强，不引入新中间件 |
| G4：调优闭环 | 按 Agent 维度的注入率/写入量/失败量为 Phase 5 的记忆配置调优提供数据支撑 |

## 成功指标

| 指标 | 目标 |
|---|---|
| 观测指标覆盖 | 本阶段定义的 10 类指标全部可从观测页/API 查询，数值与数据库直查一致 |
| 告警发现时延 | 告警条件触发到告警记录落库 ≤ 2 个检查周期（默认 ≤ 30 分钟） |
| 告警准确性 | 误报率（告警后 24h 内被人工标记为误报的比例）≤ 20%（上线后首月观测） |
| 维护漏跑可发现 | 任一维护任务（TTL/衰退/规则扫描）漏跑超 2 个周期必产生告警 |
| 零新中间件 | 不引入 Redis/独立监控栈，检查任务复用 memory Worker 周期扫描框架 |

## 范围

**包含**：

- 观测指标扩展（基于现有表直查聚合，不建新流水线）：
  - 任务健康：pending/running/failed 数量、最老 pending 年龄、按 kind 执行耗时；
  - embedding：失败数、重试成功数、积压数；
  - 检索：vector/text 调用分布、降级次数、空结果率、平均结果数；
  - 维护健康：最近一次 TTL/衰退/规则扫描执行时间；
  - Agent 维度：按 agent_id 统计注入率、写入量、失败量；
  - 注入明细：平均注入条数、flag/profile/event 分布（依赖 Phase 6 明细表，无则按 `memory.injected` 事件计数口径降级）；
  - 质量：pending 确认率、拒绝率；
- 轻量告警检查任务（复用 memory Worker 周期扫描）：
  - `memory_tasks` 15 分钟内 failed > 0；
  - 最老 pending 任务年龄 > 1 小时；
  - embedding 失败持续增长；
  - vector 降级率 > 20%；
  - 24 小时无成功维护任务执行；
  - 规则扫描超 2 个周期未执行；
  - pending 积压超阈值；
- 告警记录：写 `audit_records`（`memory.alert.*` action），观测页展示告警列表；
- 可选：Webhook 外发（单 URL 配置，失败不重试风暴，有冷却）。

**不包含**：

- 完整监控告警栈（Prometheus/Grafana/Alertmanager）的对接——平台级可观测性建设单独立项；
- 告警的分级路由、值班轮换、工单联动；
- 记忆质量的语义级评估（抽取准确率抽样评估走 evaluation 模块，不在本阶段）；
- 指标的长期归档与降采样（PG 直查 + 时间窗过滤即可，量级未到）。

## 风险与约束

- **告警风暴**：每类告警需有冷却窗口（同类告警默认 1 小时内不重复），冷却参数平台级配置；
- **观测查询成本**：聚合 SQL 直查行表，需限定时间窗（默认 24h/7d），避免全表扫描拖垮观测页；注入明细指标依赖 Phase 6 表的索引设计；
- **quickstart 形态可用**：告警检查任务跟随内嵌 Worker，两容器体验形态下同样生效，不依赖独立 memory-worker 部署；
- **阈值默认值保守**：初期阈值宁缺勿滥，先上线观测再收紧，避免初期噪音淹没真实问题。
