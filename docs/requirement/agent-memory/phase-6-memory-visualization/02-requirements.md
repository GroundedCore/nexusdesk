# Phase 6 · 客户记忆可视化与注入可解释性 — 需求文档

## 用户故事

**US-1（客服主管）**：我在客户列表就能看到每个客户的记忆规模与待确认数量，优先处理积压多的客户。

**US-2（运营）**：客户投诉"Agent 乱说话"时，我能查那次对话实际注入了哪几条记忆，快速定位是不是某条错误记忆导致的。

**US-3（运营）**：我点开一条记忆，能看到它的完整来龙去脉：什么时候从哪个会话抽取的、谁改过、改过什么、被衰退过没有、最近被哪些会话用过。

**US-4（坐席）**：我在会话工作台能看到当前这次对话用了客户的几条记忆、具体内容是什么，回答客户时心里有底。

**US-5（QA/研发）**：联调时我能从某条记忆反查它最近被注入到哪些 run，验证衰退/过滤逻辑是否符合预期。

## 功能需求

### FR-1 注入明细落库（`memory_injection_log`）

| 项 | 说明 |
|---|---|
| 记录粒度 | run × item：每次 run 注入的每条记忆一行（含 flag 小节条目） |
| 字段 | `run_id`、`customer_id`、`item_id`、`section`（flag/profile/preference/event/summary）、`score`（注入时排序分，含 effective_confidence）、`injected_at` |
| 写入方式 | run 结束时批量插入（复用 finish 同事务或异步任务），**不在 run 热路径逐条写** |
| 事件兼容 | `memory.injected` runtime event 保留既有计数字段（`items/flags/events`），payload 增加 `item_ids` 列表 |
| 保留期 | 默认 90 天，随每日 TTL 任务清理（与 event TTL 任务同车） |
| 历史数据 | 上线前的 run 无明细，界面展示"无注入明细记录" |

### FR-2 客户记忆总览（第一层）

客户列表在既有查询能力上补充记忆统计列：

| 列 | 说明 |
|---|---|
| 记忆总数 | active + pending 条目数 |
| 分类条数 | 画像 / 偏好 / 事件 各多少条 |
| 待确认数 | pending 条数（>0 时高亮，点击直达待确认 Tab） |
| 服务标记 | vip / complaint_risk / blacklist 徽标 |
| 最近更新时间 | 该客户所有条目 max(updated_at) |

支持按待确认数、记忆总数排序与按服务标记筛选。

### FR-3 客户详情 Tab（第二层）

既有客户详情重构为 Tab 结构：

```text
概览 | 画像 | 偏好 | 事件 | 服务标记 | 待确认 | 注入记录 | 审计记录
```

| Tab | 内容 |
|---|---|
| 概览 | 客户身份信息 + 各类记忆统计 + 最近更新 + 最近注入时间 |
| 画像/偏好/事件 | 既有 `MemoryItemTable` 按类型分 Tab（编辑/删除/恢复能力不变），展示字段见 FR-5 |
| 服务标记 | flag 条目管理（沿用 Phase 4 打标/解除能力） |
| 待确认 | 该客户的 pending 队列（沿用确认/拒绝） |
| 注入记录 | 该客户最近被注入的记录：时间、run/会话链接、注入条目数、可下钻到当次明细（FR-4） |
| 审计记录 | 该客户的 `memory.*` 审计时间线：操作、操作人/来源、时间、明细（不含明文内容，同 Phase 4 C4 红线） |

### FR-4 注入记录视图

| 入口 | 视图 |
|---|---|
| 客户详情 · 注入记录 Tab | 按时间倒序的注入事件列表（run 维度），展开可见当次注入的条目明细（key、类型、小节、score） |
| 会话/Run 视图 | 当次 run 的注入明细：注入了哪些条目、各属哪个小节、score 多少；点击条目跳单条记忆详情 |
| 单条记忆详情 | 该条目最近 N 次被注入的记录（时间、run 链接、section、score） |

### FR-5 单条记忆详情（第三层）

| 区块 | 内容 |
|---|---|
| 完整字段 | key、content、type、status、confidence、effective_confidence（查询时计算）、source_type、source_ref、protected、created_at、updated_at、last_referenced_at、reference_count、revision、prev_content |
| 内容 diff | `prev_content` 与当前 content 对比展示（有 prev_content 时） |
| 来源跳转 | source_ref 指向的会话/工单可跳转查看 |
| 生命周期时间线 | 由审计记录还原：创建（抽取/人工/规则）、编辑、确认/拒绝、衰退迁移、恢复、淘汰、合并归并，按时间排列 |
| 最近注入 | 见 FR-4 |

### FR-6 会话工作台联动

| 项 | 说明 |
|---|---|
| 既有抽屉增强 | `CustomerMemoryDrawer` 增加"本次对话注入"视图：当前会话各 run 的注入明细 |
| 空态 | 客户未绑定/无注入时展示明确空态文案，不报错 |

## 非功能需求

- 注入记录查询按 `customer_id + injected_at`、`item_id + injected_at`、`run_id` 建索引，P95 ≤ 2s；
- 客户详情各 Tab 懒加载，首屏 P95 ≤ 1.5s（万级条目客户）；
- 注入明细批量写入对 run 完成路径的额外耗时 ≤ 50ms（P95）；
- 权限：viewer 只读全部视图；编辑/删除/恢复/打标沿用 operator 权限；租户隔离不变；
- 审计时间线、注入明细均不展示 PII 明文之外的额外敏感面（沿用 Phase 4 C4：审计 payload 本无明文；注入明细只存 id 不存内容）。

## 验收标准

| # | 场景 | 预期 |
|---|---|---|
| AC-1 | 完成一轮绑定客户的对话 | `memory_injection_log` 按 run × item 落明细；`memory.injected` 事件计数字段不变且新增 item_ids |
| AC-2 | 客户列表 | 记忆统计列正确（与库直查一致）；待确认数 >0 高亮可点击；按标记筛选生效 |
| AC-3 | 客户详情各 Tab | 八个 Tab 数据正确；画像/偏好/事件分 Tab 的编辑/删除/恢复既有能力回归通过 |
| AC-4 | 注入记录 Tab | 按时间倒序展示；展开某次注入可见条目明细（key/类型/小节/score） |
| AC-5 | 从会话视图查看当次注入 | 列出当次 run 注入的全部条目；点击条目跳详情 |
| AC-6 | 单条记忆详情 | 完整字段齐全；prev_content diff 正确；时间线含创建/编辑/衰退等事件；来源会话可跳转 |
| AC-7 | 从条目反查注入 | 展示该条目最近被注入的 run 列表，链接可跳 |
| AC-8 | 上线前的历史会话 | 注入记录视图展示"无注入明细记录"空态，无报错 |
| AC-9 | 高频对话压测 | 注入明细写入不阻塞 run 完成（P95 额外耗时 ≤ 50ms）；无逐条 INSERT |
| AC-10 | 90 天前注入明细 | 随 TTL 任务清理，界面不再展示 |
| AC-11 | viewer 角色 | 全部视图只读；跨租户访问 404 |
| AC-12 | 客户删除后 | 其注入明细随删除级联清理（或按删除语义置空关联），界面无残留可溯内容 |
