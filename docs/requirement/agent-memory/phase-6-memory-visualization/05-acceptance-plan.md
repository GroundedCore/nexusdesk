## 4. 排障情景 UAT（核心业务价值验证，计时执行）

**情景**：运营收到投诉"Agent 刚才对客户乱承诺"。执行路径：

1. 从会话记录定位问题 run → 查看当次注入明细（A5 路径）；
2. 发现可疑条目 → 点开条目详情，看来源会话与修改历史（A6 路径）；
3. 确认错误记忆 → 编辑纠正（或删除），查看该条目还被哪些近期 run 注入过（A7 路径），评估影响面；
4. 记录全流程耗时。

**通过判据**：全程界面操作无需查库/翻日志；总耗时 ≤ 5 分钟；每一步信息充分支撑下一步决策。

## 5. 业务指标验收

| 指标 | 目标 | 测量方法 |
|---|---|---|
| 明细落库覆盖率 | 100% | 抽检：有 `memory.injected` 事件的 run 必有对应明细行（自动化对账脚本） |
| 排障回溯能力 | 会话↔条目双向可查 | §4 UAT |
| 生命周期完整度 | 有审计即有时间线点 | A6 + P6-IT-09 |
| 排障耗时 | ≤ 5 分钟 | §4 计时 |
| 性能 | 热路径 P95 额外 ≤ 50ms；查询 P95 ≤ 2s | A9 + 接口计时 |
