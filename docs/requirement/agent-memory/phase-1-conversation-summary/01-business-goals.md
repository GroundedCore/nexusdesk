# Phase 1 · 会话摘要记忆 — 业务目标

> 阶段：Phase 1（MVP）
> 预估工期：~1 周
> 依赖：无（不改身份体系、不加新业务表）

## 要解决的问题

### 问题 1：长对话早期信息丢失

Agent 运行时将 `history[-history_turns * 2:]` 之外的消息直接丢弃（`backend/src/agent_platform/modules/agent_runtime/engine.py`），默认只保留最近 10 轮。典型受损场景：

- 客户第 1 轮说明"我对花生过敏"，第 15 轮 Agent 推荐产品时给出含花生的方案；
- 客户开场描述的故障现象、已尝试的排查步骤，在多轮工具调用后从上下文消失，Agent 反复追问；
- 复杂售后对话（30+ 轮）后半段，Agent 失去对问题全貌的理解，回答质量明显下降。

### 问题 2：人工接管摘要信息不足

当前转人工时，摘要是"取最近 10 条消息拼接"（`backend/src/agent_platform/modules/human_handoff/service.py`）。长对话下坐席看不到早期关键信息，需要重新向客户询问，体验差且降低坐席效率。

## 业务目标

| 目标 | 说明 |
|---|---|
| G1：长对话上下文连续 | 被滑动窗口截掉的早期对话以摘要形式保留在上下文中，Agent 对整个会话保持"记忆" |
| G2：提升接管效率 | 坐席接管时看到"滚动摘要 + 最近消息"，无需向客户重复询问已提供的信息 |
| G3：零配置生效 | 对存量 Agent、存量渠道会话透明生效，不需要租户做任何配置变更 |

## 成功指标

| 指标 | 基线（现状） | 目标 |
|---|---|---|
| 长对话（>20 轮）中 Agent 引用早期信息的正确率（评估集抽样） | 信息丢失即错 | ≥ 90% |
| 坐席接管后向客户重复询问已提供信息的比例（人工抽检） | 高频 | 下降 ≥ 50% |
| 摘要引入的额外 token 成本 | 0 | 单轮注入 ≤ 800 tokens |
| 摘要生成延迟对 run 的影响 | 无 | 异步生成，不阻塞回复 |

## 范围

**包含**：
- 会话滚动摘要的生成、存储、注入；
- 人工接管摘要改用"滚动摘要 + 最近消息"；
- 租户级 / Agent 级开关。

**不包含**（属于后续阶段）：
- 跨会话记忆（Phase 2）；
- 客户画像与偏好（Phase 2）；
- 工单事件联动（Phase 3）；
- 摘要内容的人工编辑与治理（Phase 4）。

## 风险与约束

- **LLM 成本**：每次发生历史截断时触发一次摘要调用。对话轮次越多触发越频繁，但单次输入仅是"旧摘要 + 被丢弃消息"，体量可控；demo/mock 模型环境下不产生真实成本。
- **摘要质量**：摘要丢失细节的风险通过"摘要 + 最近 N 轮原文"的双层结构兜底，近期细节永远以原文为准。
- **兼容性**：不改变 `history` JSONB 的现有结构与写回逻辑，新增独立字段，失败时降级为现状（纯滑动窗口）。
