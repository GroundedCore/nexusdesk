# Phase 5 · Agent 记忆配置开关 — 业务目标

> 阶段：Phase 5
> 预估工期：~1 周
> 依赖：Phase 1-4（已上线）；与 Phase 6/7 无硬依赖，可并行

## 要解决的问题

### 问题 1：已有开关未暴露，运营无法自助配置

后端已存在三个 Agent 级记忆开关（`memory_enabled` / `memory_write` / `summary_enabled`），但智能体配置页没有完整暴露，调整记忆行为只能改库或改配置，运营与实施同学无法自助。

### 问题 2：开关粒度过粗，无法按场景裁剪

现有开关是"全开/全关"的粗粒度：不能只要摘要不要长期记忆（知识问答场景）、不能开读取但关闭自动写入（高合规场景）、不能限制记忆类型与注入/检索条数（成本与噪声控制）。结果是所有 Agent 共享一套记忆行为，差异化场景需求无法满足。

### 问题 3：写入策略一刀切

Phase 2 的 pending 待确认队列已支持"低置信记忆人工确认"，但是否走人工确认由全局置信度阈值决定，无法按 Agent 配置"全部自动写入"或"全部人工确认"。高合规行业（金融、医疗）要求按 Agent 收敛。

### 问题 4：配置优先级无明确规则

平台级策略（PII 脱敏、衰退、容量淘汰等）与 Agent 级开关的优先关系没有成文规则，存在"Agent 配置绕过平台合规策略"的隐患。

## 业务目标

| 目标 | 说明 |
|---|---|
| G1：配置可见可改 | 智能体配置页完整暴露记忆配置，运营/实施自助调整，无需改库 |
| G2：按场景裁剪 | 支持摘要/长期记忆/读/写/检索独立开关，记忆类型可选，注入/检索条数可调 |
| G3：写入策略分级 | 支持 `auto`（自动写入 + 低置信进 pending）与 `review`（全部人工确认）两档写入策略 |
| G4：只能收紧不能放宽 | 平台级治理策略（PII/衰退/淘汰/隔离等）不允许 Agent 关闭；Agent 只能在全局开启的基础上收紧 |
| G5：预设模板 | 提供面向典型场景的预设配置，降低配置门槛与误配风险 |

## 成功指标

| 指标 | 目标 |
|---|---|
| 智能体配置页记忆配置完整暴露 | 9 项配置全部可见可改，保存即生效（新会话生效） |
| 配置优先级正确性 | 全局关闭时 Agent 开启不生效（自动化断言覆盖全部配置项） |
| 预设模板覆盖 | ≥ 5 套预设（普通客服/高合规客服/知识问答/短期问答/演示） |
| 旧数据兼容 | 存量 Agent 迁移后行为与升级前完全一致（默认配置映射验证） |
| 高合规场景落地 | `review` 模式下全部抽取记忆进入待确认队列，无一自动生效 |

## 范围

**包含**：

- Agent 记忆配置模型扩展：会话摘要、长期记忆总开关、读/写开关、记忆类型、检索开关、写入策略、注入上限、检索上限；
- 配置优先级规则落地：平台级 > Agent 级（Agent 只能收紧）；
- 智能体配置页"记忆"分组表单（含联动置灰与说明文案）；
- 预设配置模板（一键应用）；
- 存量 Agent 配置迁移（旧三开关 → 新配置的语义保持映射）。

**不包含**：

- 平台级治理配置的管理界面（PII/衰退/淘汰等保持配置文件管理，见"不交给 Agent 的能力"）；
- 配置的版本管理与变更审批流（平台审计已记录配置变更，审批流后续单独立项）；
- 按客户/按会话维度的记忆策略覆写（超出 Agent 粒度，暂不支持）。

## 平台级能力清单（不交给 Agent 配置）

以下能力固定在平台级，Agent 配置不暴露、不可关闭、不可放宽：

- PII 脱敏（`memory_pii_masking_enabled`）
- 记忆衰退（`memory_decay_*`）
- 容量淘汰（`memory_max_items_per_customer`）
- 客户删除/合并
- flag 白名单（vip / complaint_risk / blacklist）
- embedding profile
- 租户级数据隔离
- 规则扫描周期（`memory_rule_scan_interval_minutes`）

## 风险与约束

- **存量行为不变是红线**：迁移必须保证存量 Agent 行为逐位一致，迁移前后需自动化对比注入段内容；
- **配置生效时机**：配置变更对已进行中的会话不强刷，新会话生效（避免会话中途上下文结构突变）；
- **预设不可滥用**：预设只是初始模板，应用后各配置项仍可独立调整，不做"预设锁定"。
