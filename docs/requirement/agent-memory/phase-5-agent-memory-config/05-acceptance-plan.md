# Phase 5 · Agent 记忆配置开关 — 验收方案

> 状态：待实施（本阶段上线前执行）
> 创建：2026-10-17
> 依据：`01-business-goals.md`（成功指标）、`02-requirements.md`（AC-1~AC-11）；测试执行依据见 `04-test-plan.md`

## 1. 验收目标与组织

确认本阶段交付物**配置可见可改**（10 项配置完整暴露）、**优先级正确**（只能收紧不能放宽）、**存量零影响**（升级前后行为逐位一致），并给出签字结论。本阶段的特殊性：**最大风险不在新功能而在存量回归**，存量等价是一票否决项。

| 角色 | 职责 |
|---|---|
| 产品负责人 | 验收主持；表单交互与预设体验判定；P2 遗留处置签字 |
| QA | AC 场景执行与记录；存量等价专项；回归结论 |
| 研发负责人 | 环境保障；升级前后对比数据出具；缺陷修复 |
| 实施/运营代表 | 预设模板与配置流程的 UAT 判定 |

## 2. 验收环境与前置条件

| 环境 | 用途 |
|---|---|
| 类生产环境（真实模型 + pgvector PG） | 功能验收、存量等价对比 |
| quickstart 双容器 | 降级形态下配置门控同样生效 |

**前置条件**：`04-test-plan.md` 全部用例通过（阻断项全绿），无 P0/P1 未关闭；验收环境预置若干"升级前创建"的存量 Agent 与累积客户记忆数据。

## 3. 功能验收清单（对应 AC-1~AC-11）

| # | 验收步骤 | 通过判据 |
|---|---|---|
| A1 | 打开智能体配置页（operator 与 viewer 各一次） | 10 项配置按 4 组展示、默认值正确；viewer 全部只读 |
| A2 | 关闭"客户长期记忆"总开关，保存后发起新会话 | 子项置灰；注入段无客户记忆；无 memory_search 工具；会话结束无抽取任务 |
| A3 | 配置"只读不写"后对话 | 既有记忆正常注入；无新记忆产生 |
| A4 | 写入策略设 `review`，进行含画像信息的对话 | 全部抽取记忆进待确认队列；确认前不注入；确认后下一会话注入 |
| A5 | 记忆类型仅勾选"客户画像"后对话 | 仅 profile 注入与写入；preference/event 不注入、不写入（库中无新增） |
| A6 | 平台关闭注入（`memory_inject_enabled=false`），Agent 配置全开 | 运行时无注入；表单对应项禁用并提示"平台已禁用" |
| A7 | Agent 注入上限设为 999 保存并对话 | 保存时提示截断；实际注入不超过平台上限 |
| A8 | 逐套应用预设并保存 | 表单值符合预设表；应用后可再修改；行为符合预设语义（重点验证高合规 = review） |
| A9 | 存量 Agent（升级前创建）升级后直接对话 | 注入段内容与升级前同场景 fixture 逐位一致；配置页展示映射后的值 |
| A10 | 会话进行中修改 Agent 记忆配置 | 当前会话行为不变；新会话按新配置 |
| A11 | 修改任意记忆配置并保存 | 平台审计记录操作人、变更前后值 |

每个场景执行记录：执行人、日期、环境、前置数据、实际结果、判定、截图/日志链接。

## 4. UAT 操作清单（实施/运营代表执行）

- 按五个真实场景各创建一个 Agent（普通客服/高合规/知识问答/短期问答/演示），用预设 + 微调完成配置，全流程无研发介入；
- 高合规场景完整走一遍"对话 → 待确认 → 确认 → 下次对话生效"；
- 对配置项文案与分组可理解性打分（不理解即提缺陷，文案类 P3）。

## 5. 存量等价专项（本阶段独有，一票否决）

| 步骤 | 判据 |
|---|---|
| 升级前在验收环境用固定脚本跑 N≥5 个典型会话场景，留存注入段与运行时事件 | fixture 归档 |
| 升级后同数据同脚本重跑 | 注入段逐位一致；memory.injected 计数一致；抽取/摘要任务行为一致 |
| 存量 Agent 配置直查 | 旧三键值不变；新字段为默认值 |

## 6. 业务指标验收

| 指标 | 目标 | 测量方法 |
|---|---|---|
| 配置完整暴露 | 10 项全部可见可改 | A1 核对清单 |
| 优先级正确性 | 全局关闭时 Agent 开启不生效 | A6 + 自动化断言（P5-UT-02/03 参数化全组合报告） |
| 预设覆盖 | ≥ 5 套 | A8 |
| 存量兼容 | 行为逐位一致 | §5 专项 |
| review 语义 | 全部进待确认 | A4 + P5-IT-03/04 |

## 7. 合规核对

| # | 核对项 | 判定 |
|---|---|---|
| C1 | 平台级能力（PII/衰退/淘汰/flag 白名单/embedding profile/租户隔离/规则扫描周期）不出现在 Agent 配置表单与 API 响应 | 一票否决 |
| C2 | 全局关闭任何能力时，无任何 Agent 配置组合可使其生效（自动化全组合断言常驻） | 一票否决 |
| C3 | 配置变更有审计（操作人、前后值） | 必须通过 |
| C4 | 回滚路径明确：含新字段的快照在旧代码下的处置脚本已准备并演练 | 必须通过 |

## 8. 通过标准与签字

- **通过**：A1~A11 全部通过；**§5 存量等价专项与 C1/C2 为一票否决项**；无 P0/P1 遗留。
- **有条件通过**：仅 P2/P3 遗留且每条有 owner 与期限。
- **不通过**：任一否决项触发，修复后重验受影响项 + Phase 1-4 全量回归。

输出《Phase 5 验收报告》：AC 执行记录表、存量等价对比数据、合规核对结果、UAT 记录、遗留清单、结论与签字（产品 / QA / 研发 / 实施代表）。
