## 4. UAT 操作清单（运营/客服主管执行）

- 打标/解除标记（vip / complaint_risk / blacklist）；
- 待确认队列处理 pending 建议（含人工保护产生的 `key:suggested` 条目）；
- expired 条目恢复；
- 客户合并（二次确认流程、合并后记忆完整性抽查）；
- 客户删除（二次确认流程）；
- 观测页记忆卡片解读（指标含义清晰、可指导阈值调整）。

## 5. 端到端 UAT 旅程（跨阶段综合验收）

本阶段验收时执行完整旅程（对前置阶段的累积验证）：

1. **首访**：客户经渠道进线 → 25 轮对话（含过敏史、订单号）→ 摘要生效 → 转人工，坐席确认 handoff summary 完整 → 会话结束，画像/偏好被抽取（部分进 pending）。
2. **运营动作**：坐席在 pending 队列确认正确条目、拒绝一条错误条目、人工修正称呼 → 打 VIP 标记。
3. **复访**：同身份再进线 → Agent 英文问候 + 尊称 + 提及待跟进 → 创建工单 → 坐席标记承诺"48 小时退款" → 工单 resolved。
4. **三访**：客户问"退款到了吗" → Agent 引用承诺与解决结论（检索命中近期事件优先）。
5. **治理闭环**：客户要求删除数据 → 执行删除 → 验证无残留与审计 → 该身份再进线为全新客户，历史记忆不可见。

每个环节记录截图/日志，全部通过则签署整体（Phase 1-4）验收结论。

## 6. 业务指标验收

| 指标 | 目标 | 测量方法 |
|---|---|---|
| 人工编辑 30 天内被自动覆盖比例 | 0% | 上线后审计对账：human 条目的 update 来源逐条核查（自动化校验脚本） |
| 删除执行完整性 | 100% | 删除后自动化校验：全表按 customer_id/identity 扫描无残留 + 向量列随行清除验证 |
| PII 脱敏覆盖率 | ≥ 99% | 全库扫描脚本：对 memory_items.content 跑 PII 模式匹配，明文命中数 / 应脱敏总数 |
| 注入保鲜度 | ≥ 80% | 观测统计：注入集中 90 天内被引用过的条目占比 |
| 衰退误伤率 | ≤ 5% | 上线后 30 天：expired 条目中被人工恢复的比例 |

## 7. 合规核对

| # | 核对项 | 判定 |
|---|---|---|
| C1 | PII 脱敏不可逆、原值不落库（含 prev_content 与审计 payload） | 一票否决 |

## 8. 通过标准与签字

- **通过**：A1~A13 全部通过；**A4（PII）与 A5（删除闭环）为一票否决项**；业务指标前三项为硬指标（后两项允许上线后观测期内跟踪）；合规项全过；无 P0/P1 遗留。
- **有条件通过**：仅 P2/P3 遗留且每条有 owner 与期限，硬指标达标。
- **不通过**：任一否决项触发或硬指标未达标，修复后重验受影响项 + 回归。
