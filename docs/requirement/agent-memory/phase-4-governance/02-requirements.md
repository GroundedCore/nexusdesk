# Phase 4 · 治理与标记记忆 — 需求文档

## 用户故事

**US-1（运营管理员）**：我手动修正了客户的姓氏后，不希望下一轮自动抽取又把它改回去。

**US-2（客服主管）**：我希望给 VIP 客户打标，Agent 接待时使用更周到的语气和策略；给有投诉升级历史的客户打标，Agent 避免刺激性问题并更快转人工。

**US-3（合规负责人）**：客户要求删除个人数据时，我一键执行，系统级联清除其全部记忆与向量数据，并生成可审计的删除记录。

**US-4（运营管理员）**：同一客户在两个渠道各有一个档案，我希望能合并为一个客户，记忆归并不丢失。

**US-5（平台运营）**：我希望在观测页看到记忆的抽取量、命中率、待确认积压，评估记忆质量并调整阈值。

## 功能需求

### FR-1 人工保护（防覆盖）

| 规则 | 说明 |
|---|---|
| 人工条目免疫 | `source_type='human'` 的条目：自动抽取的 `update` 操作对其降级为新建 pending 建议（不直接覆盖），人工确认后才生效 |
| 抽取条目可被抽取更新 | `source_type='extracted'` 条目之间正常覆盖（Phase 2 行为不变） |
| 人工编辑即升格 | 任何条目被人工编辑后 `source_type` 变为 `human` |
| 解除保护 | 控制台提供"恢复自动管理"操作，`source_type` 回到 `extracted` |

### FR-2 标记记忆（flag）

| 项 | 说明 |
|---|---|
| 受控标记 | `vip` / `complaint_risk` / `blacklist` 三类（key 固定，content 为标记说明） |
| 写入权限 | 仅控制台人工操作（`source_type='human'`）与内置规则（`source_type='rule'`）；抽取器输出 flag 类型一律拒绝 |
| 内置规则（硬编码 2 条） | ① 工单超时未响应（超过 `due_at` 且仍 open/in_progress）→ 自动标 `complaint_risk`；② 规则触发 30 天内无新超时 → 自动解除 |
| 注入优先级 | flag 条目在注入段最前，独立小节 `【服务标记】`，不受 20 条上限挤压 |
| 黑名单行为 | `blacklist` 存在时：Agent 注入"谨慎服务，涉承诺一律转人工确认"指令；可选配置直接自动转人工 |

### FR-3 PII 脱敏

| 项 | 说明 |
|---|---|
| 时机 | 抽取写入前 + 人工编辑保存前，对 content 执行模式替换 |
| 模式 | 手机号（保留前 3 后 2）、身份证（保留前 6 后 4）、银行卡（保留后 4）、邮箱（本地名首字符 + 域名） |
| 原则 | 脱敏不可逆，原值不落库；profile 的 `phone` 等条目同样脱敏存储 |
| 配置 | `memory_pii_masking_enabled` 默认 true；关闭需平台级显式配置 |

### FR-4 客户删除（"忘记我"）

| 项 | 说明 |
|---|---|
| 入口 | 控制台客户详情页"删除客户"（二次确认）+ API `DELETE /api/memory/customers/{id}` |
| 级联动作 | ① memory_items 物理删除（含 embedding 列随行清除）；② memory_identities 物理删除；③ runtime_conversations.customer_id 置 NULL（会话与消息保留）；④ 工单 customer_id 保留但标记为已注销引用（仅 UI 展示"客户已删除"）；⑤ Milvus/向量存储删除预留接口调用 |
| 审计 | 写入 audit_records：操作人、时间、删除条数；客户数据本身不留存 |
| 后续行为 | 该外部身份再次进线时按新客户重新建档（原记忆不可恢复） |

### FR-5 客户合并

| 项 | 说明 |
|---|---|
| 入口 | 控制台客户详情页"合并到…"，选择目标 customer，二次确认 |
| 动作 | 源客户的 identities 全部改挂目标；items 逐条归并：同 (type,key) 冲突时保留更新时间较新者，人工条目优先于抽取条目；源 customer 删除 |
| 审计 | 完整记录源/目标 ID、归并条数、冲突取舍明细 |

### FR-6 衰退机制（记忆保鲜）

**设计原则：衰退改变的是"置信度和可见性"，不是"是否存在"——一律软过期（`expired`），可恢复、可审计。**

**FR-6.1 按类型差异化的置信度衰减**

| 类型 | 半衰期（默认） | 衰减到底后的处理 | 理由 |
|---|---|---|---|
| profile | 365 天 | 跌破阈值 → 不再注入/检索，转入 pending 再确认（而非直接过期） | 姓名等长期有效，电话/地址会变；直接删除损失大 |
| preference | 90 天 | 跌破阈值 → 降权不注入，再降 → expired | 偏好会漂移，但漂移前往往有信号 |
| event | 30 天（排序衰减，Phase 3 已含）+ 180 天硬 TTL | 硬 TTL → expired | 事件参考价值随时间快速归零 |
| flag | 不衰减 | 仅规则解除或人工变更 | 标记是运营决策，时间不能替人做决定 |
| protected（人工条目） | 免疫 | 永不衰退、永不淘汰 | 人工纠正过的记忆被系统"忘掉"是治理闭环的背叛 |

- `effective_confidence = confidence × 2^(-age / 半衰期)`，age 基于 `last_referenced_at`；
- 跌破 `memory_decay_min_confidence`（默认 0.3）：停止注入与检索，按上表路由 pending 或 expired。

**FR-6.2 引用强化（使用让记忆保值）**

| 强化信号 | 级别 | 实现 |
|---|---|---|
| 客户对话中再次提及同 key 事实 | L1 最强 | 同键 upsert 时刷新 `last_referenced_at`（Phase 2 已含，零成本） |
| `memory_search` 命中且被工具结果消费 | L2 | 命中条目异步刷新 |
| 注入条目与当轮用户消息关键词重叠（近似"被引用"） | L3 保守近似 | 批量异步刷新，可采样限流 |

- 强化**只重置衰退时钟、不提升 base confidence**，误判无害；
- 强化刷新走异步批量，绝不在 run 热路径逐条写库；
- 效果目标：常用的记忆历久弥新，无用的记忆自然消亡。

**FR-6.3 容量淘汰（兜底）**

- 单客户记忆条目硬上限（默认 200 条，`memory_max_items_per_customer`）；
- 超出时按 `effective_confidence` 从低到高淘汰为 expired（protected 除外）；
- 防抽取 bug 或恶意对话刷爆单客户记忆。

**FR-6.4 可审计与可恢复**

- 每次衰退状态变迁（active→pending/expired、淘汰）写审计，含变迁前 effective_confidence；
- 控制台条目列表展示 effective_confidence 与 last_referenced_at，支持从 expired 恢复（恢复即刷新时钟）。

### FR-7 观测指标

接入 `ObservabilityService` 新增记忆维度：

| 指标 | 说明 |
|---|---|
| 抽取量 | 按日：新增/更新/pending/丢弃 各多少条 |
| 命中率 | 注入了记忆的 run 占比；memory_search 工具调用次数与空结果率 |
| 积压 | 当前 pending 条目数、最老 pending 年龄 |
| 治理 | 人工编辑次数、删除执行次数、PII 脱敏命中次数 |
| 衰退 | 每日衰退过期量（按类型）、强化刷新量、容量淘汰量、expired 恢复率 |

## 非功能需求

- 删除操作同步执行（数据量小，单客户百级条目），P99 ≤ 2s；
- 所有治理操作（编辑/删除/合并/打标）均写 audit_records，与平台审计风格一致；
- PII 脱敏为纯函数，无外部依赖。

## 验收标准

| # | 场景 | 预期 |
|---|---|---|
| AC-1 | 人工修改 name 条目后，对话中客户再次自报不同姓名 | 不覆盖人工值，生成 pending 建议 |
| AC-2 | 给客户标记 vip 后进线 | Agent 回复体现优先服务；标记位于注入段最前 |
| AC-3 | 工单超过 due_at 未响应 | 自动打上 complaint_risk；30 天无复发自动解除 |
| AC-4 | 抽取内容含手机号 13812345678 | 入库为 138******78 形态，全库无明文 |
| AC-5 | 执行客户删除后 | items/identities 无残留；会话 customer_id 为 NULL；审计记录完整；该身份再进线为新客户 |
| AC-6 | 合并两个客户（含同键冲突：一边人工一边抽取） | 冲突保留人工条目；源客户消失；审计含取舍明细 |
| AC-7 | 观测页 | 记忆维度指标正常展示 |
| AC-8 | 一条 preference 条目 200 天未被引用（半衰期 90 天） | effective_confidence 跌破阈值，不再注入；条目状态为 expired 可恢复 |
| AC-9 | 同一条目期间被客户再次提及（同键 upsert） | 衰退时钟重置，继续正常注入 |
| AC-10 | 一条 protected 条目 500 天未被引用 | 不衰减、不淘汰，正常注入 |
| AC-11 | profile 条目长期未引用跌破阈值 | 转入 pending 再确认队列而非直接 expired |
| AC-12 | 单客户条目数超过硬上限 | 每日任务按 effective_confidence 从低到高淘汰至上限内，审计含淘汰明细 |
| AC-13 | `memory_decay_enabled=false` | 无衰退计算与状态迁移，行为与 Phase 3 一致 |
